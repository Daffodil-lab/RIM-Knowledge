# 8.1 完成図・互換監査

プレイヤーは必要最低限の知識を持ち、便利そうな組合せ、極端な数量、連打、取消、接続変更、全Pawn休眠、Disk輸送、途中のMOD追加・除去を試すと仮定する。UIから可能な操作で無限資源、無限容量、遠隔瞬間移送、Quest破壊、復旧不能、セーブ肥大が起きる場合、プレイヤーの誤用ではなく製品側の欠陥として扱う。

未知MODへの互換は次の五段階で記録する。

| 判定 | 意味 |
|---|---|
| Native Safe | 通常の格納、生産、往復を保証する |
| Opaque Stasis | 元instanceを一体として停止保存できるが分解・自動生産しない |
| Adapter Required | 専用境界がなければ安全に扱えない |
| Quarantined | 反復例外または危険signalにより現在セーブで自動停止した |
| Refused | 元所在を維持して入庫・生産を拒否する |

「全MOD対応」は書かない。格納Thing、Recipe、Pawn Design、Archiveの依存ManifestとPre-uninstall導線を用意しても、外部MODを外した後にDefやclassが欠落すれば元instanceを完全自動復元できない場合がある。この限界を隠さず、安全化してから外す手順を提示する。

通常UIは生産、消費、流通の三主題を維持する。互換問題は件数、影響、次の操作へ集約し、packageId、class、stack trace、Manifest差分はDiagnosticsへ遅延表示する。
