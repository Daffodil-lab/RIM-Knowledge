## 最終判定

**勲章の文化概念だけを設定クラスとして改稿採用する。それ以外は旧資料の形では採用しない。**

二冊に書かれた他の設定、機能、数値、一覧、フォルダー構成、実装方式、進行計画は、見出しごとの個別留保を残さず、次のいずれかとして処理する。

1. 現在も必要でなければ放棄する。
2. 目的やプレイヤー体験だけが現在も必要なら、旧方式を継承せず、現行の正史所有者と実装所有者から別の方法で新規設計する。
3. 同じ概念がすでに現行OKFで独立して正史化されている場合は、旧資料ではなく、その現行所有者の権威によって存続する。

旧決定履歴に同じ案が残っていても、この判定の例外にはならない。履歴は当時の判断を記録するだけで、旧方式を再び現役にしない。

## 勲章として継承する範囲

継承するのは、功績、奉仕、救援、労働、研究、防衛、文化活動等を記憶し、公に顕彰する**勲章が存在する**という文化概念である。個人だけでなく共同体の功績も顕彰し得る。

次は勲章そのものではなく、旧資料に結合されていた旧方式であるため継承しない。

- 旧五称号の固定カタログと実在指導者名
- 旧獲得条件、受章回数、累積カウンタ
- 常時バフ、能力や遺伝子の段階解放
- 職級、評議員、議長、指揮権、技術アクセスとの自動連動
- 宇宙船級資源による強制授与
- Hediff、RoyalTitle、Permit、Favor、Recipe、Quest等の指定方式
- 栄誉を条件とするMOD解禁、研究解禁、勝利、超越、エンディング

勲章の個別名称、意匠、授与主体、授与理由、公開文面は、[勲章と顕彰](/world/32-勲章と顕彰.md)の下で一件ずつ新設する。ゲーム効果が必要な場合は、設定クラスから分離した担当実装が、勲章と直結しない方法も含めて設計する。

## 二冊の他要素

| 旧資料中の領域 | 最終処理 |
|---|---|
| 世界設定、人物、組織、政治、宗教、身体、技術 | 二冊からは不採用。既存の現行所有者に同じ概念がある場合だけ、現行記述として存続 |
| 職級、ゼノタイプ、特性、宣伝インプラント、保守要求、温度、身体ロードアウト | 旧方式を放棄。必要な体験は現行身体正史と担当実装から別設計 |
| 装備、兵器、企業、派閥、研究、拡張MOD、終盤構想 | 旧一覧と旧接続関係を放棄。必要な品や組織は設定クラスの新規概念として一件ずつ再提案 |
| 射程、性能、素材、コスト、工数、製造時間、出現率、報酬 | 不採用。担当実装が現在のゲーム規模から決める |
| ダイアログ、タブ、UI、Def、XML、C#、フォルダー構成 | 旧方式を放棄。現在の要件と実装境界から再設計 |
| フェーズ、工数見積、依存関係、進捗、リスク、完成判定 | 過去の計画として失効。現行ロードマップへ移さない |
| 勲章以外のエンディング、超越、最終目標 | 旧方式を放棄。個別ゲームの勝利は世界史の終焉にしない |

この包括判定により、二冊の全見出しは「勲章の設定クラスだけ改稿採用、他は放棄または別設計」として審査済みである。二冊を再読して旧仕様を拾い直す必要はなく、新しい提案は現行OKFから始める。
