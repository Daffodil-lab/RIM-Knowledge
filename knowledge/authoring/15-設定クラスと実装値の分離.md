# 15. 設定クラスと実装値の分離

設定資料は、**何がこの世界にあり、どう理解されるか**を所有する。実装資料は、**それを現在のゲーム規則でどう動かすか**を所有する。同じ項目の中へ両者を混在させない。

## 設定クラスへ置くもの

- 対象の存在と分類
- 表示名、通称、カタログ上の系統
- アーカイブ番号、種類コード、型式名、改修記号
- 歴史的な由来、文化的な位置、典型的な使用者
- 発注者と、発注目的・発注理由
- 設計した組織または個人、製造した組織、権利や設計を継承した主体
- 要求定義、試作、試験、採用、改修、派生型等の開発経緯
- 当初の開発目的を達成したか、何を達成できず、どのような代替用途を得たか
- 軍、警察、救援組織、民間利用者、整備担当等による評価
- 現在の生産、配備、退役、予備保管、払い下げ、復刻、遺物化等の状況
- 用途、運用思想、他クラスとの定性的な違い
- 外見の方向、手触り、音、使用感
- フレーバーテキスト、人物や組織との関係
- 「近距離向け」「携帯しやすい」「辺境で修理しやすい」等の定性的な性格
- 銃器の口径、使用弾薬規格、全長、銃身長、非装填時重量、標準装弾数、作動方式等の世界内物理仕様
- 遠距離武器が弾薬結晶から何を現地生成するか、生成・保持・装填をどの構造で行うか
- 改造身体、高度装備、設備が外部エネルギー供給を必要とするか、外地でエネルギー結晶を使うか
- バイポッド、トライポッド、銃架、交換銃身、冷却装置等を備えるかという構造上の事実
- 「過熱しやすい」「耐久性が低い」「汚れに弱い」等、利用者が認識する定性的な欠点

設定カタログは、まだゲームへ実装されていない品を含めてよい。カタログへ存在することは、ThingDef、Recipe、研究、画像、バランス値が完成していることを意味しない。装備・軍事カタログは継続追加される開放型カテゴリであり、現在の候補数、採用数、実装数を総数や完成上限として扱わない。

## 実装へ置くもの

- Def名、クラス名、XMLまたはコード上のフィールド
- 射程、命中率、ダメージ、貫通、発射間隔、CE上の`magazineSize`等の性能値
- 耐久、ゲーム上の`Mass`と`Bulk`、品質、価格、資産価値
- 低温状態から銃身または機関部が加熱限界へ達するまでの発射数
- 一発・一斉射ごとの加熱量、射撃停止後の冷却速度、安全温度と常温へ戻るまでの時間
- 銃身交換の可否、交換時間、予備銃身、必要技能・工具、交換後に引き継ぐ熱と摩耗
- 基礎ジャム率と、熱、耐久、汚損、弾薬、品質、環境による補正
- ジャム解除時間、射撃不能、命中・反動悪化、持続射撃による耐久減少・破損等の欠点
- バイポッド等の展開・収納時間、展開条件、反動・精度・揺れへの効果、移動・射角・姿勢制限
- 弾薬結晶の携行、武器別変換率、現地生成時間、装填、射撃消費、補給UI・AI
- 常設エネルギー接続、エネルギー結晶の容量・消費、供給不足時の機能制限・安全停止
- 実際に消費する素材、素材数、Stuff規則
- Recipe、作業量、製造時間、設備、研究、技能条件
- 入手率、報酬量、出現条件、装備優先度
- グラフィックパス、音声パス、互換パッチ、保存形式

ゲーム内の説明欄へ表示される文章でも、世界内の意味を説明するフレーバーは設定クラス、現在のStatを説明する自動表示や数値文は実装に属する。

ゲームエンジンがPawnへ性別、空腹、睡眠、呼吸、出血等の既存フィールドを要求する場合、その設定値は互換・表示・ゲーム進行のための実装上のAdapterとして扱う。`Gender.Female`等の便宜的な値を、シオンに生物学的性別、人間型の内臓、生理現象が存在するという正史根拠へ逆輸入しない。シオンの身体に何が存在しないかは設定クラスが所有し、どのNeedsやHediffを無効化、置換、流用するかは実装が所有する。

## 設定・実装共有項目

設定クラスと実装クラスの分離は、両者が同じ情報を使用することを禁止しない。**世界内の事実がそのままゲームの入力値になる項目**は、設定と実装を結ぶ共有項目として扱う。

代表例は、標準弾倉の装弾数、銃身数、利用可能な射撃モード、単発装填か一括装填か、使用弾薬規格等である。これらは設定カタログで製品仕様を説明すると同時に、実装Defの挙動を拘束する。

ただし、同じ事実へ二つの独立した正本を作らない。共有項目には次のいずれかの対応関係を明記する。

| 対応 | 意味 | 例 |
|---|---|---|
| 完全共有 | 設定値と実装値を同一にする | 標準弾倉30発 → CEの`magazineSize` 30 |
| 単位変換 | 同じ事実をゲーム側の単位へ変換する | 世界内重量3.2kg → CEの`Mass` 3.2 |
| 派生 | 設定値を根拠に複数のゲーム値を調整する | 全長・銃身長 → `Bulk`、`SwayFactor`、射程 |
| Adapter | エンジン制約のため別表現へ置換する | 特殊な多重投射弾を一回分の弾薬消費として表現 |
| 独立調整 | 世界内事実と直接対応せず、ゲームバランスだけで決める | 市場価値、出現率、研究費 |

共有項目の意味上の所有者は設定クラスとし、実装はその値を参照または投影する。完全共有または単位変換で異なる値を使う場合は不整合である。Adapterまたは独立調整で差を設ける場合は、実装資料に変換規則と理由を記録する。

設定カタログが「耐久性が低い」「過熱しやすい」「連続射撃に向かない」等を製品の欠点として明記した場合、その欠点は実装を拘束する共有項目である。実装は、単なるフレーバーへ降格させず、ジャム、加熱限界、冷却待ち、銃身交換、摩耗、射撃性能低下、破損等の一つ以上へ具体化する。

## 装備カタログの由来・開発・評価

装備カタログは、完成品の名称と仕様だけでなく、その品が作られ、使われ、評価され、現在へ残った経緯を設定クラスとして所有する。原則として次の欄を設ける。

| 項目 | 記録する内容 |
|---|---|
| 発注者 | 国家、評議会、軍、警察、救援組織、公社、工房、企業、共同体、個人等 |
| 発注目的・理由 | 解決を求めた問題、想定任務、既存品への不満、政治・産業・補給上の事情 |
| 要求事項 | 携帯性、耐環境性、威力、整備性、共通部品、低価格化等、当初求められた定性的要件 |
| 設計者 | 設計した組織、設計局、工房、企業、公社、共同体または個人 |
| 製造者 | 試作・量産・ライセンス生産・現地再生産を担当した主体 |
| 開発経緯 | 前身、試作、競争試作、試験、事故、設計変更、採用、改修、派生型、製造移管 |
| 目的達成 | 当初目的を達成したか、部分達成か、失敗か。成功した点、残った問題、想定外の用途 |
| 利用者 | 典型的な配備先、職種、地域、時代、民間または軍務上の利用層 |
| 利用者評価 | 操作、信頼性、整備、携行、補給、訓練、心理的受容等に関する現場の評価 |
| 制度上の評価 | 採用機関、試験部門、調達部門、歴史家、展示機関等による公式評価 |
| 現在の状況 | 試作中、制式採用、限定配備、量産中、生産終了、退役、予備役、払い下げ、復刻、遺物、所在不明等 |
| 評価時点 | どの年代、型式、配備先の評価か。後年の改修前後を混同しない |

発注者、設計者、製造者は同一とは限らないため分けて記録する。設計権の移転、ライセンス生産、複数組織の共同開発、現地改修がある場合も、それぞれの役割を区別する。

「開発目的を達成した」は、単純に高性能だったという意味ではない。性能が優れていても、高価、複雑、補給困難、政治的事情、想定任務の消滅等によって採用に失敗し得る。逆に当初要求を満たさなくても、別任務、民間用途、辺境での再利用によって長く使われることがある。

利用者評価は一つの総評へ潰さない。公式試験、指揮側、実際の使用者、整備担当、補給担当、民間利用者では評価軸が異なってよい。相反する評価がある場合は、使用型式、環境、時代、任務を併記して両方を残す。

現在の状況は、ゲーム上の出現率や入手可否を直接確定しない。「退役済み」は世界内の制度上の状態であり、辺境の倉庫、払い下げ市場、遺跡、個人所有から出現しないという意味ではない。実際の出現率、価格、報酬、研究解禁は実装が所有する。

発注者や設計者が不明、秘匿、異説ありの場合は、無理に一人へ確定しない。「公式記録」「利用者間の通説」「後世の異説」を分離し、不確実性自体を設定として保持する。

## 銃器カタログの物理仕様

拳銃、小銃、機関銃、散弾銃等の銃器カタログには、原則として次の欄を設ける。これはゲームバランス値ではなく、世界内でその製品がどのような物体・機械であるかを示す設定クラスである。このうち装弾数等は、同時に実装を拘束する共有項目にもなる。

| 項目 | 記録する内容 | 設定・実装の関係 |
|---|---|---|
| 口径・使用弾薬 | 口径、薬莢長、弾薬規格、専用弾または互換弾の系統 | 弾薬DefとAmmoSetを選ぶ根拠。ID自体は実装 |
| 全長・銃身長 | 通常使用時の全長と、弾道へ寄与する銃身の長さ | `Bulk`、取り回し、弾道値への派生元 |
| 重量 | 原則として弾薬、弾倉、付属品を含まない非装填時重量 | CEの`Mass`と単位共有できる。装填状態を明記する |
| 装弾数 | 標準弾倉、固定弾倉、弾倉筒、回転弾倉、ベルト等の基準容量 | 原則としてCEの`magazineSize`と完全共有 |
| 作動方式 | 発射原理・動力源と、必要に応じて駆動、閉鎖、給弾機構 | 射撃Verb、反動、発射間隔、射撃モード等の根拠 |
| 支持・冷却・交換装置 | バイポッド、トライポッド、銃架、放熱器、冷却装置、交換銃身の有無と構造 | 展開、冷却、交換、姿勢制限等の実装根拠 |
| 信頼性上の欠点 | 過熱、摩耗、汚損、弾薬選択、部品寿命等に関する定性的な弱点 | ジャム、性能低下、冷却待ち、破損等の実装を拘束 |

**作動方式は一欄の中で二層に分けてよい。**

1. 発射原理・動力源：化学装薬、圧縮ガス、電磁加速、指向性エネルギー、外部電源等。
2. 機構：手動、半自動、全自動、選択射撃、ガス圧作動、反動利用、ブローバック、回転式、ベルト給弾等。

架空技術で詳細をまだ決めていない場合は、もっとも上位の原理だけを記し、機構を未確定としてよい。銃身を持たない兵器へ銃身長を捏造する等、非該当欄を無理に埋めない。値が未確定なら「未確定」、構造上存在しないなら「非該当」と区別する。

全長は折畳・伸縮・換装状態がある場合に基準状態を明記する。重量は非装填時、装填時、標準付属品込み等の条件を明記する。装弾数は薬室内一発を含むかを明記する。

## 過熱・信頼性・銃身交換

銃身加熱、ジャム、摩耗、破損はバニラ環境でもCombat Extended環境でも成立させる中核実装仕様とする。CE互換パッチだけへ閉じ込めない。

### 加熱と冷却

最低限、次を決める。

- 冷えた状態から加熱警告までの発射数
- 冷えた状態から安全限界または射撃停止限界までの発射数
- 一発、点射、一斉射ごとの加熱量
- 射撃停止後、再射撃可能になるまでの冷却時間
- 安全限界から基準温度へ戻るまでの時間
- 外気温、雨、真空、水中、屋内外、能動冷却等を反映するか
- 過熱段階ごとの命中、散布、反動、発射速度、ジャム率、耐久への影響

「何発で加熱するか」は試験条件を併記する。原則の基準は、標準弾薬、標準銃身、初期温度、通常環境、最高持続射撃モード、冷却支援なしとする。単射と全自動、標準弾と高圧弾で結果が異なる場合は別に扱う。

冷却時間は、単一の「完全に冷える時間」だけでなく、**再射撃可能温度へ下がる時間**と**基準温度へ戻る時間**を分けてよい。プレイヤーとAIが待つべき時間は前者を使う。

### 銃身交換

交換銃身を持つ武器では、次を決める。

- 交換可能になる条件と、交換を推奨または強制する熱量
- 交換作業時間
- 交換中の移動・射撃可否
- 予備銃身を独立アイテム、弾薬・装備枠、抽象化された消耗品のどれで扱うか
- 工具、技能、姿勢、銃架、補助要員を要求するか
- 取り外した熱い銃身の冷却と再利用
- 銃本体の機関部に残る熱と摩耗
- 銃身寿命、交換失敗、火傷または機体損傷等を扱うか

銃身交換時間は設定カタログの物理仕様と実装を結ぶ共有項目になり得る。ただし、ゲーム時間へ圧縮する場合はAdapterとして換算理由を記録する。

### ジャム、摩耗、破損

耐久性または信頼性が低いと設定された武器は、少なくとも次の一つ以上を実装する。

- 平常時または条件付きのジャム
- 過熱時のジャム率上昇
- 耐久低下、汚損、粗悪弾、非対応弾、悪環境によるジャム率上昇
- ジャム解除に必要な時間、技能、工具または部品
- 過熱による命中、散布、反動、発射速度の悪化
- 大量射撃による武器HPまたは内部耐久の減少
- 銃身、機関部、給弾部の破損と射撃不能
- 修理、部品交換、銃身交換を行うまで残る性能低下
- 明示的に採用する場合のみ、暴発、弾薬誘爆、射手への損傷等の重大故障

設定上の欠点を実装できない製品段階では、その欠点を削除せず実装予約として残す。「耐久性が低い」と説明しながら、通常品と同じ信頼性で欠点なく射撃できる状態を完成仕様にしない。

ジャムや破損は、発生確率だけでなく、プレイヤーへの警告、解除操作、AIの対処、保存・読込、装備交換時の状態保持まで仕様化する。AIが過熱したまま破損まで連射し続ける場合は、意図した人物像または難易度設計でない限り不合格とする。

## バイポッド・支持装置

バイポッド、トライポッド、銃架、車載架等について、設定クラスは装置の存在、構造、標準装備か追加装備か、想定姿勢、運用思想を所有する。実装は次を所有する。

- 展開と収納に必要な時間
- 展開可能な地形、遮蔽物、姿勢、射角
- 展開中の反動、揺れ、散布、照準時間、連射制御への効果
- 未展開時の重量・Bulk・取り回し上の不利益
- 展開中の移動、旋回、対象変更、近接戦闘への制限
- 再配置時に自動収納するか
- プレイヤー操作、Gizmo、表示状態、アニメーション、効果音
- AIが展開、収納、再配置、撤退を判断する条件
- 支持装置の耐久、破損、修理、換装を扱うか

Combat Extendedで既存の`Bipod_*`系`weaponTags`と同等の挙動が得られる場合はCE側の機構を利用する。バニラ環境では、同じ中核仕様を独自Comp、状態、Job、Gizmo等のAdapterで表現する。クラス名とフィールド名は実装時に確定し、この設定規則から架空のCEフィールドを作らない。

バニラ用とCE用を同時に有効化して、反動軽減、加熱、ジャム、耐久減少等を二重適用してはならない。CEの存在を検出した場合は、どの中核機能をCE側へ委譲し、どの独自機能だけを残すかを互換資料で明示する。

## Combat Extended実装へ渡す情報

[Combat Extended](https://github.com/CombatExtended-Continued/CombatExtended)対応では、設定カタログの物理仕様と共有項目を根拠にしつつ、次の情報群を実装資料または互換パッチへ置く。外部MODのフィールド名と挙動は変更され得るため、実装時には対象CE版のリポジトリと[Compatibility Patch Guide](https://github.com/CombatExtended-Continued/CombatExtended/wiki/Compatibility-Patch-Guide)を再確認する。

### 銃本体

- 対象`ThingDef`、親Def、`defName`
- `Mass`、`Bulk`、`SightsEfficiency`、`ShotSpread`、`SwayFactor`、`RangedWeapon_Cooldown`
- `CombatExtended.Verb_ShootCE`、`defaultProjectile`、`warmupTime`、`range`
- `recoilAmount`、`ticksBetweenBurstShots`、`burstShotCount`
- 発砲音、銃口炎、対象条件
- `weaponTags`、片手・二手、二脚、固定火器等の条件付きタグ
- 銃床、銃身、銃口等を近接攻撃へ使う場合の`CombatExtended.ToolCE`
- CE既存機構で表現できない加熱、ジャム、銃身交換、破損を扱う独自Compまたは互換Adapter

### 弾倉・再装填・射撃モード

- `CombatExtended.CompProperties_AmmoUser`
- `magazineSize`、`reloadTime`、`ammoSet`
- 一発ずつ装填する場合の`reloadOneAtATime`
- `CombatExtended.CompProperties_FireModes`
- 単射、連射、制限点射、照準射撃、制圧射撃、AI射撃モード

設定上の標準装弾数とCEの`magazineSize`は、通常は完全共有する。ただし、散弾、多重投射、特殊弾倉、チャージ消費、複数銃身等で一発と一回の射撃が一致しない場合はAdapterとし、換算規則を実装資料へ明記する。

シオン装備体系の全遠距離武器は弾薬結晶を必要とする。CEで具体的な`AmmoDef`を使う場合も、弾薬結晶からその弾薬を現地生成する変換工程または再装填Adapterを持たせる。CE側の弾薬消費と独自の結晶消費を二重に課さない。

### 弾薬と弾道

- `CombatExtended.AmmoSetDef`による弾薬ThingとProjectileの対応
- 汎用弾薬モードへ対応する場合の`similarTo`
- `CombatExtended.AmmoDef`、`ammoClass`、弾薬の`Mass`、`Bulk`、市場価値、カテゴリ
- `CombatExtended.ProjectilePropertiesCE`
- 弾速、基礎ダメージ、Sharp・Blunt貫通、薬莢排出、追加効果
- 弾薬製造を行う場合の`RecipeDef`、材料、製造数、`workAmount`

口径と弾薬規格は、どの`AmmoSetDef`を使うか、または新設するかを判断する設定根拠になる。ただし、口径だけからダメージ、貫通、弾速を決めない。弾頭構造、弾種、装薬、銃身長、架空技術上の発射原理、CE内の比較基準を実装側で合わせる。

### 設定からCEへの対応表

| 設定クラスまたは共有項目 | CE実装で検討する主な項目 | 対応 |
|---|---|---|
| 口径・使用弾薬規格 | `AmmoSetDef`、`AmmoDef`、`ammoClass`、`defaultProjectile` | 派生 |
| 全長・銃身長 | `Bulk`、`SwayFactor`、`ShotSpread`、射程、二手・二脚タグ | 派生 |
| 非装填時重量 | 武器の`Mass` | 原則として単位共有 |
| 標準装弾数 | `magazineSize` | 原則として完全共有 |
| 給弾・装填方式 | `reloadTime`、`reloadOneAtATime` | 方式は共有、時間は派生 |
| 発射原理・作動機構 | `Verb_ShootCE`、反動、発射間隔、射撃モード、薬莢排出 | 方式は共有、数値は派生 |
| 加熱・冷却・交換銃身 | 発射時加熱、冷却処理、交換Job、予備銃身、UI、AI | 欠点は共有、数値と方式は派生 |
| 低耐久・低信頼性 | ジャム、摩耗、武器損傷、修理、状態保存 | 欠点は共有、確率と損傷量は派生 |
| バイポッド等の支持装置 | `Bipod_*`タグまたは独自Adapter、展開状態、効果、AI | 装置は共有、効果量は派生 |
| 弾種と弾頭構造 | Projectile、ダメージ、Sharp・Blunt貫通、速度、追加効果 | 派生 |
| 照準器・銃床・二脚・付属品 | `SightsEfficiency`、`SwayFactor`、`weaponTags`、必要なComp | 派生 |

## 拳銃の判定例

| 設定クラス | 実装 |
|---|---|
| 拳銃という分類、カタログ名 | `ThingDef`と内部ID |
| 誰が何のために発注し、誰が設計・製造したか | 表示文、関係するFaction・Quest・入手経路を実装する場合の根拠 |
| 試作、試験、採用、改修等の開発経緯 | 型式別Defや研究順を作る場合の根拠 |
| 目的を達成したか、利用者がどう評価したか | 性能値を自動決定せず、フレーバーと設計意図の根拠にする |
| 現在は制式、予備、退役、払い下げ等のどの状態か | 出現条件、入手率、価格を決める際の根拠 |
| 護身用、携帯用、副武装という用途 | 射程、命中率、ダメージ、貫通 |
| 同盟旧制式、民間品、帝国遺物等の歴史層 | 研究前提、出現率、techLevel |
| 口径と使用弾薬規格 | `AmmoSetDef`、`AmmoDef`、Projectileへ派生 |
| 全長と銃身長 | `Bulk`、`SwayFactor`、`ShotSpread`へ派生 |
| 非装填時重量 | `Mass`と原則共有 |
| 標準弾倉30発 | `magazineSize` 30として完全共有 |
| 火薬式、反動利用、半自動等の作動方式 | 射撃Verb、反動、発射間隔、射撃モードへ派生 |
| 過熱しやすい、耐久性が低いという欠点 | 発射数閾値、冷却時間、ジャム、摩耗、破損として実装 |
| 交換銃身とバイポッドを備える | 銃身交換時間、予備銃身、展開時間、射撃補正、移動制限として実装 |
| 小さく取り回しやすいという使用感 | warmup、cooldown、携行負荷 |
| 白い外装や真鍮色の装飾という視覚方向 | `stuffDef`、材料数、テクスチャパス |
| カタログ本文とフレーバーテキスト | Recipe、workAmount、製造時間 |

身体外形でも同じ分離を行う。頭頂まで約165～170cm、狐耳込み約230～250cm、人間耳を持たないことは設定クラスである。Pawnの`drawSize`、当たり判定、遮蔽、扉通過、帽子や髪の描画アンカーは実装値であり、設定上の全高から自動決定しない。

設定上どうしても特定素材でなければ成立しない固有品は、その素材を設定事実として明示できる。その場合も、材料数、Recipe、工数は実装が所有する。バランス変更だけを理由に、設定上の由来やフレーバーを黙って書き換えない。

## 文書化規則

1. 一つの旧項目に設定と数値が混在していた場合、先に設定クラスの概要を抜き出す。
2. 数値、素材、工数、Def、Recipeは実装資料または実装予約へ移す。
3. 設定クラスから実装所有者へリンクし、実装側は従う設定クラスを`normative_basis`で示す。
4. 実装されていない設定クラスを「存在しない」と扱わない。
5. 実装値が未決でも、カタログ名とフレーバーだけを理由なく実装予約へ送らない。
6. ある時点の装備候補を全件監査しても、装備・軍事カテゴリ自体を完結または凍結したとは扱わない。
7. 新規装備の追加と、既存装備を現在の製品段階で実装するかの判断を分離する。
8. 銃器カタログでは、口径、全長、銃身長、重量、装弾数、作動方式を設定クラスとして記録する。
9. 装弾数等、世界内の事実がそのままゲームの入力値になるものは共有項目とし、完全共有、単位変換、派生、Adapter、独立調整のどれかを明記する。
10. 共有項目に二つの独立した正本を作らない。実装値は設定所有者を`normative_basis`として参照する。
11. CE互換仕様は外部依存である。実装時の対象バージョンを記録し、カタログ正史をCE側の変更へ追従させない。
12. 装備カタログには、発注者、発注目的、設計者、製造者、開発経緯、目的達成、利用者評価、現在の状況を可能な範囲で記録する。
13. 公式評価と現場評価、設計者と製造者、制式上の退役と実物の残存を同一視しない。
14. 設定で過熱、低耐久、低信頼性を欠点として採用した場合、バニラとCEの双方で加熱、冷却、ジャム、摩耗、破損、銃身交換等へ具体化する。
15. 加熱までの発射数、再射撃可能までの冷却時間、銃身交換時間には試験条件とゲーム時間への換算規則を付ける。
16. バイポッド等は装置の存在を設定、展開時間、射撃補正、姿勢・移動制限、AI挙動を実装として記録する。
17. バニラ用AdapterとCE用Adapterで同じ効果を二重適用しない。
18. シオン装備体系の全遠距離武器について、弾薬結晶から固有弾薬または射出単位を現地生成する設定と実装を持たせる。[Human Weapons計画](/design/44-Human-Weapons計画設定クラス.md)の人間用通常工学火器はこの体系へ含めず、化学装薬を封入した通常弾薬を使う。
19. エネルギー結晶は弾薬結晶と別資源とし、改造身体・高度装備・設備の外地稼働へ用いる。標準シオン全員の一律な空腹代替Needへしない。
20. 同盟装備の設定クラスには[装備アーカイブ番号体系](/design/46-装備アーカイブ番号体系.md)に従う番号と種類コードを持たせ、実装側は形式、重複、分類対応を検証する。
