# 8. 製品・内部モジュール別の責務境界

| 領域 | 担当 | 固定境界 |
|---|---|---|
| Core Base | 通常シオン、標準遠征身体、最初の小規模独立開拓団開始、独立勢力派閥基盤、β版Pawn Foundry | α版の三人開始を独立開拓団全体の規模・政体へ一般化せず、派閥を一枚岩にしない。Pawn生成・登録・Clone・Dormant・回収はKombinatではなくCoreが所有する |
| Red Star（配布境界未決） | 本国、正式派遣開拓団、優れた継続支援、正式任務、報告・監査、救援・交戦責務 | 支援と責務を対にし、本国支援をCore全体の標準にしない。Core同梱／外部配布をまだ固定しない |
| Core独自保管・接続システム（α以後） | Network、実Thing保管・検索・直接入出庫、容量、Endpoint、任意排出、保存・復旧 | Coreが正本在庫と公開予約・入出庫契約を所有する |
| Kombinat（Core常駐追加層） | 通貨Account、取引、Factory Buffer、発注、多段生産、消費観測、目標在庫、流通優先度 | Core独自基盤の公開入出庫へ接続し、生産・消費・流通・通貨の責務を所有する |
| The Hive（Core同梱予定・β後期） | 例外的な単一中枢運営と非人型端末 | α版は固有実装も空の将来境界も置かない。通常生成から隔離し、Core完成宣言までに任意モジュールとして完成させる |
| 内戦拡張 | 帝国内戦、革命戦争、失われた規格と記録 | 帝国全史を一様な悪へ還元しない |

[五つの代表工業資源](/world/33-代表工業資源.md)はCell、エネルギー結晶、構造材、保守資材、弾薬結晶であり、全て実Thingとする。[エネルギー](/world/40-エネルギー.md)は上位ジャンル、[凝縮真空](/world/35-凝縮真空.md)はその中に属する技術または形態である。[同盟通貨](/world/39-同盟通貨.md)だけをAccount残高とする。KombinatはFactory Buffer、通貨Account、Request、Plan、Job、Batch、目標在庫、消費表示、流通優先度、保存、Adapter、試験を所有する。実装済み範囲とRelease Gateは[現在地](/roadmap/08-現在地.md)が所有する。人口、労働、研究、名声、防衛準備、装備ポイント等は各領域の状態として扱う。Patternと実行器は安全な実行を担う内部型であり、通常プレイヤーへ設定を要求しない。

同盟通貨は、実際に保有・移転・支出できる金銭残高として書く。ただし、本国の生存保障を購入する切符、名声、忠誠、政治的信用、Red Star支援資格へ置き換えない。工場の通常Recipeで無から発行せず、交易、契約報酬、決済、明示的な発行・交換Adapterを通じて増減させる。固有通貨名が決まるまでは、正史本文で`Kombinat_AllianceCurrency`や`AC`を作中固有名として使わない。

現在の実装優先順位は、Core独自保管・接続基盤、Kombinat追加層の完全な発注・多段生産・消費観測・優先度付き流通・通貨と、XML／Defで作れる最小三人開始を同じαとして完成させることである。The HiveとRed Starの固有実装や空の将来境界はαへ置かず、βで必要になった時に作る。

α公開後のβでは、Core独自保管・接続システムを大容量化・拡張し、続いてPawn FoundryをCoreへ実装する。適合するランダムPawn、既定個体、プレイヤー設計個体、登録個体、Cloneを反復生産でき、生存Pawnの人格状態、身体、内蔵Moduleを資源・通貨・専用容量・継続Tickなしで保管でき、負傷、遺体、登録個体を低コストで回復できることを必須とする。着脱装備とinventoryはDormant化前にCore独自基盤の通常入庫経路またはMapへ返却する。

Ephemeral Pawnは死亡して遺体回収・再資源化が完了したら構造化個体情報をセーブから除去する。Registered IndividualはArchiveを残し、同じ個体IDの実体を同時に一体だけ再実体化できる。Cloneは別個体IDを持つ複数Pawnとして生産し、一人とそのCloneだけのコロニーを許可する。登録の有無を人格権や身分差へ変換しない。

一つのKombinat Terminal、Factory Input／Output Buffer、具体発注、目標在庫、消費表示、優先度付き流通、多段生産、同盟通貨は実装予約ではなくα必須である。Core独自システムがStorage、接続、任意排出、資産価値、破壊時挙動をαから所有し、その不具合をCoreのRelease Gateへ数える。追加工場、高度な発注、追加Recipe、AmmoRuntime、他MOD連携、追加資源はβ以後の実装予約にできる。台帳は、帝国や同盟が何を数え、何を数えないかを表現できるが、テーマだけでデータモデルを決めず、v4のプレイ要件、不変条件、保存、性能から新規設計する。

遠距離物流、Map間・拠点間・WorldObject間のRoute、輸送中Cargo、無限距離Terminalは`docs/42_KOMBINAT_REMOTE_LOGISTICS_PROTECTED_DRAFT.md`へ保護延期する。再承認までα、β、Core／Red Star 1.0の完成条件にせず、空APIや互換予約も作らない。

Kombinatは中央保管、入出庫、backpressure、多段自動生産、中間品隔離を担う。プレイヤーが同時に判断する主題は「何をどれだけ作るか」「何がどこで消費されるか」「限られた品をどこへ先に流すか」の三つとする。操作画面、状態モデル、保存はRimWorldのThing identity、Quest参照、資産価値、停止保存を優先し、採用した外部参考と意味は詳細要件書§2へ記録する。

α／βは同一ビルドの保存・ロードを必要とするが、版間セーブ互換と移行を要求しない。Core MODとRed Starの完成宣言を伴う1.0から、維持するdataVersion、公開API、DefNameと移行責任を開始する。
