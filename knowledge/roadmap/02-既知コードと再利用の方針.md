# 2. 既知コードと再利用の方針

コード再利用は、現行責務と受入条件を満たし、出所と保守責任を説明できる単位だけに限定する。

再利用するかどうかは、次の順で判定する。

1. 現在の正史と製品責務に適合するか。
2. 最終仕様へ自然に拡張できるか。
3. 保存、失敗処理、試験、性能を説明できるか。
4. 依存方向と公開APIを悪化させないか。
5. 修正して使う方が、新しく単純に実装するより明確か。
6. 出所、ライセンス、保守責任が明瞭か。

重大な不適合がある単位は再利用対象から外し、現在の公開契約に沿う単純な実装を選ぶ。

1.0完成宣言前のコード、API、DefName、保存形式は、最終設計のために変更・置換してよい。公開α／βの実在する配布物やセーブに対しても、版間移行を実装する責任は負わない。

既存DefNameやAPIを保持する場合も、「既にあるから」ではなく、名前が妥当、移行費が高い、外部参照が存在する等の具体的理由を記録する。

再利用したコードには出所、ライセンス、採用理由、所有Assembly、試験、更新責任を記録する。実装進捗は[現在地](/roadmap/08-現在地.md)が所有し、採用済みの現行コードと通過した検証だけから判定する。
