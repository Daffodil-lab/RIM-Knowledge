# 4. α版 — 最初の公開候補

## 4.1 目的

α版は、最低限の種族MODとして継続プレイできる最初の公開候補である。Core独自保管・接続システムとKombinatは、先行する内部の工業基盤完成マイルストーンでバニラHumanによる検証を完了していることを前提とする。

αの実装責任は次の二層に分ける。

1. 内部完成したCore独自保管・接続システムとKombinatを、種族非依存の公開境界のままCoreへ常駐させる。
2. Core本体はRimWorldのXML、Def、必要なRuntimeでShion種族、標準身体、図像、開始、建築、研究、Recipe、装備、表示を最後に実装し、独立開拓団のプレイを成立させる。

Shion種族の図像不足は工業マイルストーンを停止させない。工業マイルストーン未完了の状態で、種族実装または仮画像を工業不具合の代替完成条件にしない。

## 4.2 αの提供内容

| 要素 | αの提供内容 |
|---|---|
| Coreパッケージ | `About.xml`、本体と対象公式DLCの条件、ロード順、公開候補の版表示 |
| シオン種族 | バニラHuman継承とBiotech Gene／Xenotypeによる標準身体表現、PawnKind、基礎能力、健康、死亡、装備、作業との標準接続 |
| 独立開始 | 数人規模の独立開拓団Scenario、開始Pawn、開始品、開始説明 |
| XMLコンテンツ | 最低限の名前、背景、研究、建築、Recipe、装備、説明、日英翻訳 |
| Core独自保管・接続 | 実Thing Storage、Network、Endpoint、Filter、直接転送、手動排出、保存、復旧、管理UI |
| Kombinat | 通貨Account、Transaction、Facility Profile、Storage生産予約、Pattern、Request、Plan、Job、Batch、Def駆動統合UI、保存、診断 |
| 発注・多段生産 | 全必須要件、A〜J、KX-001〜008を通す三段以上の生産縦切り |
| 同盟通貨 | 物理在庫と分離した共同Account残高、表示、Transaction |
| 保存 | 同一αビルド内の新規開始、保存、ロード、通常終了、取引復旧 |

## 4.3 必須のプレイ縦切り

```text
数人の独立シオンで開始
  → 種族、開始品、建築、Recipeを確認
  → Core独自Storage、Network、Import／Export Endpointを構築
  → 実ThingをThingOwner保管状態へ移す
  → Kombinat FactoryをStorageの入力予約・出力容量予約・生産Commitへ接続
  → 生産目標、消費表示、流通目標を設定
  → 三段の多段生産を計画・実行
  → 中間品、副産物、最終品を保管
  → 選択品、指定数、全内容物をMapへ排出
  → 障害状態と復旧結果を確認
  → 同一ビルドでセーブ・ロードして継続
```

## 4.4 α完了条件

- CoreとKombinatがRimWorld 1.6および対象公式DLC環境へロードできる。
- 新規ゲームで数人のシオンを選び、独立開拓団として開始できる。
- シオンが描画され、基本的な健康、負傷、死亡、装備、作業を行える。
- 名前、背景、開始説明、研究、建築、Recipe、装備があり、種族MODとして継続プレイできる。
- 日本語と英語の主要表示が利用できる。
- 五つの代表工業資源が実ThingDefとして機能する。
- 同盟通貨の共同Account、Transaction、Reservationが機能する。
- Core独自Storageが実Thing identityを保ち、検索、Filter、容量、入庫結果、排出を扱える。
- 自動搬入と搬送が`ThingOwner`間の直接取引で完結する。
- Plannerが受信済み在庫と予約の増分索引から在庫判断を行う。
- Kombinat Factoryが実Thingを保持せず、入力予約と出力生成を一度だけCommitできる。
- 選択品、指定数、全量をMapへ排出できる。
- `NoOutputCell`時は保管所有権を維持し、UIへ理由を返す。
- 建築実体のRecovery Interfaceが停電とNetwork分断の状態で手動排出要求を受け付ける。
- Factory需要、消費量、IO待ち、材料不足、設備待ち、転送待ちを表示できる。
- RecipeとFacilityの自動登録、blocking、output lock、Seeded Recursive Patternが機能する。
- 三段以上の生産が依存計画、入力取り寄せ、予約、中間在庫、副産物、Output Claim、最終出力保管まで機能する。
- 生産、消費、流通、通貨の操作と各状態理由をKombinat Terminalで確認できる。
- 全必須要件、A〜J、KX-001〜008、S2-001〜018を通す。
- 同一ビルド内で新規開始、複数回のセーブ・ロード、通常終了が成立する。
- 途中セーブ、ロード、施設破壊、出力満杯、再送の各経路で資源総量とThing所有権が保存される。
- 規定規模のStorage、予約索引、Facility、Plan、Job、Batch、通貨Transactionがtick、UI描画、保存、ロードの性能予算を満たす。
