# 5. β版

## 5.1 目的

β版は、α版に含めなかったコアMODとレッドスターの要素を追加し、両製品を完成へ到達させる期間である。更新は可能な限り遊べる縦切りとして加えるが、開発速度と最終設計を優先し、版間セーブ互換を制約にしない。

## 5.2 更新レーン

| レーン | 主な追加 |
|---|---|
| 種族・身体 | 機構部品、接続規約、個別調整、外見差分、身体品質、修復、交換、装飾、追加身体 |
| ポーン生産・再生 | 適合生成、既定個体、個体設計、個体記録への登録、複製、反復依頼、無料休眠保管、低コスト修復・遺体回収・再実体化 |
| 独立開始 | 漂着、認可、車輌、動物、ソフェル等の開始バリアント |
| 保管・接続基盤 | α版のコアMOD独自接続網、実在する`Thing`の保管、接続規約、搬入出、保存・復旧を大容量化し、性能・診断・拡張境界を固める |
| 独立派閥 | 拠点網、国家級勢力、民間軍事会社型組織、契約、外交、戦争・救援 |
| コンビナート | 独自保管・接続基盤上の大容量保管、高速接続端点、追加施設・製造処方、無線接続、接続網エネルギー、規模拡張 |
| 通貨・経済 | 原子的送金、交易、契約報酬、為替接続層、組織会計 |
| 技術 | 通常工学、同盟標準技術、イェツィラー、ソフェル用研究 |
| 生活・文化 | 料理、祭り、旅行、趣味、身体装飾、工芸、研究遊び |
| 救援・物語 | 救援方法、当事者証言、局所調整、関係修復、帝国／同盟比較 |
| 装備・戦闘 | 具体装備、装備群、非物理的な装備ポイント、役割別装備構成、外観多様性、武器、防具、弾薬、修理、補給、交戦規則、救命・回収 |
| 車輌・動物 | 輸送、救難、警戒、生態系、文化、愛玩 |
| バックストーリー | 少数の高品質稿から段階的に追加 |
| レッドスター | 惑星戦役の介入・抵抗・統一の三路線、段階制クエスト、支援、責務、終戦 |
| ザ・ハイヴ | 他レーン安定後の専用開始、中枢、端末、作業体、救援 |
| 品質 | 他MOD接続層、性能、翻訳、アクセシビリティ、診断、1.0以後の互換方針 |

## 5.3 βの推奨順

1. α版の独立開始、種族、コンビナート、通貨を安定化する
2. α版のコアMOD独自保管・接続システムを性能試験し、大容量化、診断、追加接続端点を実装する
3. 身体実行基盤とポーン製造所の適合生成、登録、複製、無料保管、低コスト再生
4. 独立勢力の派閥基盤
5. 国家級独立勢力と民間軍事会社型組織
6. 日常、救援、技術、装備の横幅
7. コアMOD独自基盤へ上位保管、高速接続端点、無線接続、接続網エネルギー、追加施設、契約経済を接続
8. レッドスター惑星戦役を第一章の一路線から縦切りで実装し、三路線と終戦まで拡張する
9. ザ・ハイヴの後期任意モジュール
10. 1.0候補の全体調整

レッドスターとザ・ハイヴの順は逆転させない。ザ・ハイヴは通常のコアMODと独立勢力のプレイが安定した後に着手する。

## 5.4 一更新の完了条件

βの各更新は、少なくとも次を満たす。

- 一つの明瞭なプレイ価値がある。
- 必要な定義、実行時処理、操作画面、翻訳、同一ビルドの保存責務が揃う。
- 途中セーブ、取消、破壊、無効化等の失敗経路がある場合は試験する。
- 版間移行を実装する必要はない。配布物には開発版セーブが互換でない場合があることを明記する。
- 正史・制作規約・プレイヤー説明を同期する。
- 未完成の隣接機能を操作画面へ露出しない。

## 5.5 β終了条件

βは、次を全て満たすまで継続する。

1. コアMODが§3.2および§6の完成条件を満たす。
2. レッドスターが、介入、現地抵抗、惑星統一の三路線と終戦を持つ任意の惑星戦役として完成する。
3. レッドスターのコアMOD同梱または外部配布の境界を確定し、選んだ形で公開できる。
4. コアMODとレッドスターの双方について、完成宣言を行う。
5. 1.0以後に維持する`DefName`、公開接続規約、`dataVersion`、セーブ互換方針を固定する。
6. `シオンShion_Core_β版_Pawn生産保管再生_仕様_v1.md`の全`MUST`とA〜Jを通過する。
7. ポーン製造所のADV-001〜010と、監査S-047〜060、S-064〜066のβ阻害条件を通過する。
8. コアMOD独自保管・接続システムが規定規模で完成し、Matter Networkを導入せずに代表プレイループと保存・ロードが成立する。

コアMODだけ、またはレッドスターだけを完成と呼んでもβ版は終了しない。ザ・ハイヴはコアMODへ統合された後期任意モジュールなので、コアMOD完成宣言に含める。
