# 6. β終了／1.0完成条件

1. §3.2の主要領域が代表コンテンツ付きで成立する。
2. αのプレイ縦切りが、序盤だけでなく中盤・終盤の目標へ接続する。
3. 数人の独立団、国家級独立勢力、PMC型組織が別のゲーム体験を持つ。
4. シオンの身体が工業規格による保守性と、本人ごとの一点物の構成を両立する。
5. 適合生成、既定個体、個体設計、登録個体、Cloneを反復生産し、生存Pawnを無料保管し、負傷・遺体・登録個体を低コストで回復できる。
6. Ephemeral Pawnは死亡回収・再資源化後に構造化個体情報を残さず、Registered Individualは単一個体として再実体化できる。
7. 具体装備指定と装備ファミリー指定を用途別に使い分け、ファミリー指定を安定して具体Thingへ解決できる。装備ポイントを物理在庫・通貨・資産価値にしない。
8. 五つの代表工業資源が実Thingとして生産・消費・流通し、同盟通貨が交易・契約の金融残高として別の役割を持つ。
9. 同盟通貨が生存権、名声、忠誠、Red Star支援資格と混同されない。
10. 料理、祭り、趣味、装飾、工芸、動物との生活が欠乏解消後も意味を持つ。
11. 救援が実際に成功しながら、善の定義の不一致を扱える。
12. 通常工学、同盟標準技術、イェツィラー、ソフェルを混同しない。
13. Red Starの配布境界が決まり、選んだ形で支援と責務を遊べる。
14. The Hiveが任意起動で実装され、通常シオンの代表・完成形・進化先に見えない。
15. 日本語・英語、UI、説明文、エラー表示が完成している。
16. 長期セーブ、更新移行、性能、依存欠落、機能無効化を検証できる。
17. 旧資料や既知コードを実装量の目標にせず、採用した要素の出所と理由を追跡できる。
18. 重大な既知不具合、セーブ破壊、無限資源、二重消費、通常開始への任意モジュール混入がない。
19. Core MODとRed Starの双方について完成宣言できる。
20. 1.0以後の版間セーブ互換、移行、廃止手順を製品約束として公開できる。
21. 対象RimWorld build、全DLC、互換カテゴリ、Adapter version policy、Pre-uninstall手順、既知のRefused対象を公開できる。
22. 外部MODなし、複雑Thing、Storage、Recipe、Pawn、Questの代表MODを用いた試験記録がある。
23. Core独自保管・接続システムが代表的な保管・検索・入出庫・破壊・復旧・保存を担い、Matter Networkが必須依存、Assembly参照、Def参照、保存データ前提のいずれにも残っていない。

1.0以後も、身体、派閥、クエスト、装備、料理、動物、互換Adapter等を追加できる。1.0は更新停止ではなく、完成した基盤と製品約束の開始点である。
