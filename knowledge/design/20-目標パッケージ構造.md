# 20. 目標パッケージ構造

実装時の目標例:

```text
ShionCore/
├─ About/
│  └─ About.xml
├─ Assemblies/
│  ├─ Shion.Core.dll
│  ├─ Kombinat Runtime Assembly（名称はK1で決定）
│  ├─ Core独自保管・接続Runtime（正式名称未決、α）
│  └─ Shion.Hive.dll（後期）
├─ Common/
├─ Defs/
│  ├─ Core/
│  ├─ Kombinat/
│  ├─ StorageNetwork/（正式名称未決、α）
│  └─ Hive/
├─ Languages/
├─ Patches/
│  ├─ Core/
│  ├─ Compat/
│  └─ Hive/
├─ Textures/
│  ├─ Core/
│  └─ Hive/
└─ Source/
   ├─ Shion.Core/
   ├─ Kombinat/
   ├─ StorageNetwork/（正式名称未決、α）
   └─ Shion.Hive/（後期）
```

実際のRimWorldバージョン別フォルダは対応対象が決まった時点で追加する。

Matter NetworkはこのCoreツリーへ内包せず、`About.xml`の必須依存にも追加しない。上流Source、DLL、Def、UI、Harmony patchを複製・変更しない。Core独自保管・接続Runtimeをα版から正規基盤として配置する。図中の`StorageNetwork`は責務を示す仮称であり、Assembly名・名前空間・Def接頭辞を確定しない。

Red Starは、Core同梱案でも外部案でも`Shion.RedStar`の独立Assembly／名前空間を候補とする。上のCoreツリーへ配置するか別パッケージへ配置するかは未決であり、現時点の目標ツリーへ固定しない。

## 20.1 Assembly境界

| Assembly | 参照可能 | 参照禁止 |
|---|---|---|
| Kombinat Runtime | Verse/RimWorld、必要な汎用基盤 | Shion.Core具象、Hive具象、Red Star |
| Core独自保管・接続Runtime（名称未決） | Verse/RimWorld、Coreが定める公開契約 | Matter Network Assembly、Matter Network private状態 |
| `Shion.Core.dll` | Kombinat公開Application境界、Core独自保管・接続の公開境界 | Hive具象への必須参照、Matter Networkへの恒久参照 |
| `Shion.Hive.dll` | Shion.Core公開境界、Kombinat公開Application境界 | Red Star、Kombinat private状態 |
| `Shion.RedStar.dll`候補 | Shion.Core、Kombinat公開Application境界 | Hiveの内部状態。配布パッケージは未決 |

CoreとHiveの型共有が必要なら、Core側に小さなinterface／event契約を置く。

## 20.2 Def境界

- DefNameはモジュール接頭辞を持つ。
- HiveのDefsは後期にCoreへ同梱しても、専用研究・シナリオ・条件で非表示／非生成にする。
- v4で実装する五つの代表工業資源ThingDefはCoreの必須Defとして常時ロードする。同盟通貨はThingDefにせずAccount schemaとしてロードする。
- Red Star固有Defは接頭辞を安定させ、配布境界の決定前にCore共通Defへ混入させない。
