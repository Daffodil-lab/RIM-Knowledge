# 68. カエルム支援注文と信用枠の状態機械

`CaelumSupportOrder`は、プレイヤー共同体がカエルムまたは同盟へ物資、人員、生殖支援を要請する契約単位である。既存のMarkまたはCreditで支払う注文と、認可された信用枠から追加借入を行う注文を同じ画面で扱うが、追加借入は必ず新しい債務Recordとして事前表示し、支援品受領だけで債務を黙って増やさない。

## 注文種別

| 種別 | 引渡し対象 | 契約上の完了 |
|---|---|---|
| `Goods` | 武器、衣服、薬物、原料、食品、設備等の実Thing | 指定Containerまたは着陸区域への所有権移転 |
| `TemporaryPersonnel` | 期限、任務、帰還条件を持つ支援Pawn | 到着と一時服務契約の発効。期限後は返還工程へ移る |
| `PermanentPersonnel` | 永続加入へ本人と派遣元が同意したPawn | 到着、契約確認、Faction移籍のCommit |
| `EmbryoSupport` | Biotech互換の胚またはカエラヴィ受精卵 | 医療・保管可能な実Thingとして引渡す |
| `OvaSupport` | 未受精卵子または系統指定の生殖材料 | 指定の低温保管先へ引渡す |

一時人員は所有物、囚人、購入奴隷として生成しない。契約Recordが派遣元、服務期間、許可業務、危険任務、負傷・死亡、報酬、帰還を所有する。永続人員は`PermanentPersonnel`と明示した注文だけが加入処理を行い、一時契約の期限切れを自動永続化しない。

胚、受精卵、卵子は遺伝性鳥類系統、親情報、保存状態、使用可能DLC機構を保持する。遺伝情報を解決できない注文は一般Human embryoまたは無系統品へ置換せず拒否する。

## 信用枠

`SupportCreditFacilityDef`は発行主体、利用通貨、利用可能な注文種別、上限、追加債務Profile、税・手数料、期限、審査条件を所有する。利用可能額は資産ではなく、注文Commit時まで債務でもない。

信用枠を使う注文は、見積画面に次を同時表示する。

- 既存残高から支払う額
- 新しく借りるMarkまたはCredit相当額
- 追加される債務Record、債権者、元本、契約後合計
- 軍功、返済履歴、身分等による利用条件
- 物資価値、輸送、税、手数料を分けた内訳

承認時に信用枠引出しTransactionと注文予約を同じCommitへ含める。承認前または予約失敗時は債務を作らない。発送後の輸送損失を誰が負担するかは注文Defの`riskTransferState`で明示し、不明な場合は発送を拒否する。

## 状態機械

```text
Draft
  → Quoted
  → FundingReserved
  → Approved
  → FulfilmentReserved
  → InTransit
  → Delivered
  → Settled

Draft / Quoted / FundingReserved → Cancelled
任意の処理中状態 → Suspended または Failed
```

| 状態 | 正本結果 |
|---|---|
| `Quoted` | 品目、個体、数量、価格、税、輸送、到着条件、見積期限を固定する |
| `FundingReserved` | Mark、Credit、または信用枠引出しを予約する |
| `Approved` | 注文契約と必要な追加債務を一つのTransactionで発効する |
| `FulfilmentReserved` | 派遣元のThing、Pawn、胚、卵子、Gravship枠を注文IDへ予約する |
| `InTransit` | 配送物Manifestと輸送主体を固定し、同じ荷を再生成しない |
| `Delivered` | 到着対象を一度だけWorldまたはMapへ実体化し、受領結果を記録する |
| `Settled` | 支払、税、債務、契約、所有権移転を最終照合する |

各注文は`orderId`、各配送は`deliveryId`、各Manifest行は`lineId`を持つ。同じIDの再送、Map再読込、Gravship再SpawnでThingまたはPawnを複製しない。

## Gravship引渡し

標準配送はOdysseyのGravshipが指定World tileへ到達し、プレイヤーが選んだ有効な着陸区域へ着陸して行う。注文はGravship本体を長期所有せず、配送主体ID、Manifest、到着予定、着陸条件、帰還条件だけを保存する。

- 着陸区域が無効、占有、危険、Map不在の場合は`InTransit`を維持し、代替地点を勝手に選ばない。
- 物資は着陸後に通常のThingとして生成し、標準所有Containerまたは指定搬出セルへ移す。
- 一時人員は契約発効後にSpawnし、帰還Gravship消失と同時に誤ってDespawnしない。
- 永続人員は加入Commit後だけプレイヤーFactionへ移す。
- 胚と卵子は必要保管先の容量と温度条件を事前検査し、不成立ならGravship内Manifestへ保持する。
- Gravship破壊、Map削除、保存・ロードではManifestと実Thingのどちらが正本かを配送状態から一意に決める。

## 取消、失敗、返還

- `FundingReserved`までの取消は予約をRollbackし、債務を作らない。
- `Approved`後の取消は注文Defの取消料と既発生輸送費だけを明示Transactionへ記帳する。
- 一時人員の期限到来は帰還注文を予定Queueへ入れ、全Pawnを定期走査しない。負傷、拘束、死亡、行方不明を別結果として派遣元へ報告する。
- 永続加入の同意またはFaction移籍が失敗した場合、対象Pawnを一時人員へ黙って変えず、注文を`Suspended`にする。
- 到着物の一部だけが成立した場合、成立済みManifest行と未成立行を分け、成立済み対象を再生成しない。
- 参照Def、派遣主体、Gravship、着陸先、保管先を解決できない場合は代替品を選ばず、プレイヤーに再指定を求める。

## 性能と受入条件

- 状態遷移、到着予定、契約期限をイベントと期限Queueで処理し、全注文、全Pawn、全WorldObjectを毎Tick走査しない。
- UIは注文概要と可視Manifest行をキャッシュし、閉じている間は見積を再計算しない。
- 一回の配送処理量をManifest行単位で制限し、大量注文を同一Tickへ実体化しない。
- 既存残高、Credit、信用枠借入の各注文、全五種の引渡し、取消、部分配送、無効着陸先、Gravship破壊、保存・ロードを検証する。
- 信用枠注文で債務が承認時に一度だけ増え、取消・再読込・再配達で二重増加しないことを確認する。
- 配送前は注文価値が資産へ入らず、実Thingまたは加入Pawnが到着した後だけバニラの資産計算へ現れることを確認する。
