# 13. 個体設計

旧資料には特性三層、コア特性#1〜#33、任意特性、Tier、Quality、改造ポイント、身体ロードアウト、製造ダイアログ、製造階級、職級、栄誉、研究ツリーがある。

これらは一括で現行正史とはしないが、個体設計システムの保護候補として残す。以下の身体アーキテクチャは現行の確定設計であり、旧Tier表や旧スロット数を復活させる根拠にはしない。

## 13.1 身体アーキテクチャ

シオンの身体は、次の責務へ分離する。

| 層 | 責務 | 代表的な状態 |
|---|---|---|
| `BodyPlatform` | 基礎的な材質、機構、標準インターフェース、保守方式 | 狐娘型の標準遠征基盤、互換タグ |
| `BodyInterface` | モジュールを安全に接続する規格 | 接続種別、許容負荷、排他条件、外装干渉 |
| `BodyModule` | 作業、医療、探索、戦闘、環境適応等の追加機能 | 能力、消費、重量、必要Interface、故障状態 |
| `BodyTuning` | 同じ部品を本人へ合わせる個別調整 | 感覚、応答、姿勢、出力、制御の調整値 |
| `BodyExterior` | 外観、衣服接続、装飾、自己表現 | 顔、目、耳、尾、色、継ぎ目、装飾 |
| `BodyHistory` | 使用、修理、交換、由来を示す履歴 | 製造元、修理痕、交換部品、記念的改造 |

`BodyPlatform`を共通にしても、活動中の`BodyConfiguration`はPawnごとに保持する。同じDesignまたはClone Sourceから作った場合も、生成時に各Pawnへ独立した構成状態を与え、以後の改造、損傷、装備、経験を共有しない。個体性は希少部品一個だけで表現せず、部品の組合せ、調整、外装、本人の選択、経年履歴の総体として扱う。

狐娘型は無性の共有外形である。身体設計へ生物学的な男女区分、人間型の内臓、生理現象を正史要件として持ち込まない。動力、熱管理、保守、故障等の具体値は実装Defへ置き、設定クラスの固定事項と混ぜない。

頭部外装は狐耳だけを持ち、人間耳を追加しない。狐耳の大きさと全高は設定上の共有シルエットに従うが、実際の描画倍率、装備アンカー、選択範囲、当たり判定、遮蔽、扉通過判定は実装とプレイアビリティが所有する。

モジュールは規格化された接続境界を使い、Platformのprivate実装へ直結させない。追加身体、DLC連携、外部MOD Adapterは、互換タグと検証を通じて既存構成へ加えられるようにする。

所有境界は次の通り。

- 規格、製造設備、一般部品カタログは共同体または組織が保有し得る。
- 完成した身体、保存された個体構成、個人用モジュール、外装、調整は本人に属する。
- 共同装備を一時接続しても、身体そのものが共同体所有へ変わらない。
- 修理者や製造者は作業権限を持ち得るが、所有権を自動取得しない。

## 13.2 実装データ境界

βで身体Runtimeを実装する際は、少なくとも次のデータ境界を設ける。実際のクラス名は実装時に確定できるが、責務を混ぜない。

| 境界 | 主な内容 | 保存 |
|---|---|---|
| `ShionBodyPlatformDef` | 基盤、標準Interface、互換タグ、描画入口 | Def参照 |
| `ShionBodyInterfaceDef` | 接続規格、制約、競合規則 | Def参照 |
| `ShionBodyModuleDef` | 必要Interface、効果、負荷、外装表示 | Def参照 |
| `ShionBodyConfiguration` | 使用Platform、装着Module、個別調整、外装、履歴参照 | Pawnごとの正本状態 |
| `ShionBodyCompatibilityProfile` | 衣服、武器、防具、DLC機構、外部Adapterとの適合規則 | Def／Profile参照 |
| `PawnDesign` | 繰り返し使える身体、能力、外装、Loadoutの設計 | 個体情報を持たない設計正本 |
| `IndividualArchive` | 名前、人格、技能、関係、身体等を持つ一人の復元記録 | 登録個体の正本 |
| `CloneLineage` | Clone Sourceと派生関係 | 各Cloneの個別状態とは分離 |
| `DormantPawnRecord` | 生存Pawnの人格状態、身体、内蔵Moduleの停止保存 | 無料保管中の正本 |

スロット数、Tier、Quality、改造点、全Module一覧は未確定である。Module登録、Pawn別構成、互換検証はβで成立させる。αはXML／Defによる固定の標準身体表現を許可し、それを最終的な拡張上限にしない。

## 13.3 再採用の原則

- 人格の価値を製造品質で決めない。
- Tier／Qualityは身体、部品、設備、調整精度へ限定し、人格階級と自動連動させない。
- 負特性を「欠陥人格」の烙印にしない。
- 身体ロードアウトは自己所有と生活選択に整合させる。
- 帝国期の製造階級が残る場合、同盟での法的意味と俗称を区別する。
- 特性数と数値は実装Def・UI容量・バランス試験から確定する。

## 13.4 Pawn生産方式

β版では、次の四方式を実装する。

| 方式 | ゲーム上の意味 |
|---|---|
| 適合生成 | 役割と最低能力だけを指定し、残りをランダム化したEphemeral Pawnを補充する |
| 既定個体 | Defで登録された名前、外見、身体、能力を持つ個体を生産する |
| 個体設計 | プレイヤーが身体、Module、能力、外装、具体装備／装備ファミリーを一から構成して保存・生産する |
| Clone | Registered IndividualまたはSaved Designを原型に、別個体IDのPawnを任意数生産する |

Registered Individualの再実体化は、同じ個体IDを一体だけ復帰させる。Cloneは同じ原型を持つが、各個体が独自のID、経験、関係、傷、改造、装備を持つ。この分離により、一人の登録シオンとそのCloneだけでコロニーを構成できる。

## 13.5 保管、死亡、回収

生存Pawnは人格状態、身体、内蔵Moduleを、資源、通貨、専用容量、継続Tickを必要としないDormant状態へ無料で保管・再配備できる。着脱可能な装備、衣服、工具、inventory内ThingはDormant化前にCore独自保管・接続システムの通常入庫経路またはMapへ返却し、安全な返却先がなければDormant化を完了しない。Dormant身体と内蔵Moduleは所在MapまたはWorldObjectのwealthへ算入する。

負傷修復、回収遺体の再起動、登録個体の再実体化は、標準新規Pawn生産より低コストを基本とする。Ephemeral Pawnは遺体再資源化が完了すると、Pawn、Corpse、World Pawn、Relation、Archive、個体参照付き履歴をセーブ正本から除去する。Registered IndividualはArchiveを残し、同じ個体として再実体化できる。

実装要件、ID、保存、性能、受入シナリオは`シオンShion_Core_β版_Pawn生産保管再生_仕様_v1.md`を正本とする。

## 13.6 製造ダイアログ

`Dialog_ManufacturePawn`等の旧案は、適合生成、個体設計、登録個体の再実体化、Clone、Dormant保管を混同しないUIへ再設計する。

プレイヤーは詳細設計のほか、「建築担当を一人」「この個体のCloneを十人」のような簡易注文を行える。能力値を購入する画面だけでなく、身体用途、費用、製造時間、装備不足、登録方式、記録継承を説明できる必要がある。
