# 69. カエルム軍功認定契約

`CaelumServiceLedger`は、プレイヤー共同体がカエルムとの軍務契約へ提供した軍事的貢献を軍功pointとして保存する。軍功は債務返済の代替ではなく、元本を維持したまま軍功帰還を認めるための独立評価である。

## 認定対象

軍功は次の二つのバニラ事象だけから作る。

| 事象 | 成立時点 | 認定額 |
|---|---|---:|
| `RaidEnemy` Incident | `IncidentWorker_RaidEnemy`が実行に成功し、敵Raidの発生が成立した時。Quest由来を含む | `IncidentParms.points`を1対1 |
| バニラQuest成功 | 受諾済みQuestが`QuestEndOutcome.Success`で一度だけ終了し、そのQuestに帰属する認定済みRaidが一件もない時 | `Quest.points`を1対1 |

Raidは敵を撃破した時ではなく、成功した敵対Raid Incidentが発生した時点で認定する。Raidの壊滅、撤退、降伏、コロニー敗北、敵の生存数は既に認定した額を変更しない。Incident実行が失敗して敵が発生しなかった場合は認定しない。

QuestはバニラQuest本体が所有する成功結果と`points`を利用する。報酬選択、報酬価値、個別QuestPart、MOD独自難易度から追加pointを推定しない。失敗、期限切れ、未受諾、棄却、成功以外の終了は認定しない。

## Quest由来Raidの優先認定

Questが`RaidEnemy`を発生させる場合も、Raidは成立した瞬間に必ず`IncidentParms.points`を認定する。同じQuestの成功pointを後から重ねず、Quest成功時にそのQuestへ帰属する認定済みRaidが一件以上あれば、成功Eventを`SuppressedByRecognizedRaid`として0にする。認定済みRaidが一件もないQuestだけが、成功時の`Quest.points`を認定できる。

Raid Eventは判明している`originQuestId`を保存し、Quest側は帰属するRaid Event ID集合を持つ。発生時点でQuest帰属を解決できないRaidも認定を遅らせず、まずRaidとしてCommitする。後から同一Questとの帰属が判明した場合はEvent間の関連だけを追記し、Raid軍功を取消・移動・再加算しない。Quest成功時まで帰属を解決できない場合は成功Eventを`RecognitionPending`へ置き、同じ脅威を二重認定しないことを確認してから0またはQuest成功pointを確定する。

Questと無関係なStoryteller、Faction、報復等の`RaidEnemy`は通常のRaid成立認定を受ける。Questが活動中であるという理由だけで無関係なRaidを抑止しない。

Pawnのkill、down、damage、capture、死体、戦闘ログ、敵のCombat Power、個々のRaid memberを軍功へ変換しない。撃破数を数えるためのPawn、Hediff、Damage、Death hookを追加しない。

## 数値と正本Record

軍功は`1 point = 100 service minor unit`の符号付き64 bit固定小数で保存する。元の`points`をminor unitへ変換できないNaN、Infinity、負数、桁あふれは認定せず、理由をEvent Recordへ残す。0 pointsは成功事象として記録するが、軍功残高を増やさない。

| データ | 内容 |
|---|---|
| `serviceEventId` | 一度のRaid成立またはQuest成功を識別する安定ID |
| `sourceKind` | `RaidEnemyIncident`または`VanillaQuestSuccess` |
| `sourceLoadId` | Incident発生RecordまたはQuestの保存ID |
| `originQuestId` | Quest由来の場合のQuest load ID。無関係Raidでは値を持たない |
| `recognizedRaidEventIds` | Questへ帰属し、成立時認定を受けたRaid Event ID集合。Quest成功Recordだけが持つ |
| `sourcePoints` | 事象成立時に固定した元points |
| `recognizedMinor` | 1対1変換後の軍功minor unit |
| `recognizedAtTick` | 認定時点 |
| `contractId` | 軍功を受け取る共同体契約 |
| `result` | `Committed`、`SuppressedByRecognizedRaid`、`RecognitionPending`、`Duplicate`、`Rejected`と理由 |

共同体の軍功合計は正本残高として保存し、表示時に全Eventを再集計しない。Event Recordは監査と重複防止に保持する。

## 事象捕捉と重複防止

Raid dispatcherは実行試行へ`serviceEventId`を割り当て、`RaidEnemy` workerが成功を返した後だけ認定TransactionをCommitする。同じIncident発生Record、同じ`serviceEventId`、同じMap再読込では一件だけ成立する。別のRaidが同じtickと同じpointsで発生しても別IDとして認定できる。Quest由来か未解決かにかかわらず、成立したRaidをQuest成功待ちで保留または抑止しない。

QuestはQuestの安定したload IDと成功終了を組み合わせたIDを使う。成功通知、報酬受領、Credits表示、保存・ロードが同じQuestを再通知しても二重認定しない。成功時に`recognizedRaidEventIds`が空ならQuest pointsをCommitし、一件以上なら成功Eventを0で抑止して、同じQuestのRaid Eventと成功Eventを両方加算しない。

認定Transactionは次の順で処理する。

1. 対応する有効な共同体軍務契約を解決する。
2. 事象種別、成功状態、元points、発生IDを固定する。
3. `serviceEventId`索引で既認定を検査する。
4. 1対1で固定小数へ変換し、Event Recordと軍功残高を一つのCommitで更新する。
5. 新合計、帰還閾値までの差、債務元本が変わっていないことを結果表示する。

共同体契約を解決できない事象は別契約へ黙って帰属させず、`Unassigned`として保留する。プレイヤーが契約を選び直した時だけ再処理する。

## 債務、税、通貨との境界

- 軍功加算はMark、Credit、Silver、税額、債務元本、返済累計を変更しない。
- 軍功は利息相当の軍事貢献を表すが、台帳上の元本返済Transactionではない。
- 軍功をMarkまたはCreditへ換金するUIを設けない。
- 帰還閾値を満たしても債務Recordを完済、免除、取消へ変更しない。

## 保存、性能、受入条件

- 軍功残高、全`serviceEventId`、元points、結果、契約IDをWorld saveへ保存する。
- Raid成立とQuest終了の通知だけで処理し、敵Pawn、Quest一覧、戦闘ログを毎Tick走査しない。
- 重複索引はID lookupを定数時間で行い、履歴UIはページ化する。
- points 500のRaid成立で軍功500、points 500の別Raidでさらに500、同一通知再送で追加0となることを確認する。
- Raid実行失敗、Raid敗北、敵kill 0、敵kill多数のいずれでも規定どおり成立時pointsだけを使うことを確認する。
- Quest points 100の成功で100、失敗・期限切れで0、同じ成功終了の再通知で0となることを確認する。
- Quest由来Raidは成立時に必ず認定され、同じQuestの成功pointが0で抑止されることを確認する。
- 認定Raidを発生させなかったQuestだけが、成功時に`Quest.points`を1対1で認定されることを確認する。
- Quest活動中に発生した無関係なStoryteller Raidは通常どおり認定され、Quest成功側の抑止判定へ誤って帰属しないことを確認する。
- 全認定前後で債務元本、返済累計、Mark、Credit、税が同値であることを確認する。
