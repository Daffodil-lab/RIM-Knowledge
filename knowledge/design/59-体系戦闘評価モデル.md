# 59. 体系戦闘評価モデル

本モデルは、レッドスター等の戦役級・地域級作戦を裁定するための設計正本である。マップ上で実際に行われるRimWorld戦闘の射撃、被弾、経路探索、個別Pawnの行動を置き換えない。外部軍事研究の数式をそのまま世界内法則にせず、ゲームで追跡できる状態と判断へ変換する。

## 評価原則

- 兵器名または陣営名へ固定した万能点を与えない。
- 同じ兵器でも、任務、地形、天候、電磁環境、敵の対抗手段によって寄与を変える。
- 火力だけでなく、観測、識別、通信、指揮、兵站、整備、救命、回収を戦闘システムに含める。
- ドローン、有人機、砲兵、歩兵、艦隊を別々のボーナスとして足すだけでなく、任務を完了する接続として評価する。
- 民間人保護、交戦規則、政治目的は「弱さ」ではなく、使用可能な行動を決める制約として扱う。
- 結果は確率的に裁定し、同じ入力から常に同じ損害を発生させない。

## 兵器候補から戦域可用兵器まで

兵器 `w` を戦域 `z`、時刻 `t` で投入できる条件を、次の論理ゲートで表す。

```text
Available(w,z,t) = Feasible
                AND Validated
                AND Allocated
                AND InStockOrCompleted
                AND DeliveredOrConnected
                AND Operated
                AND Sustained
                AND Authorized
```

同盟が兵器を設計・製造できることは主に `Feasible` と `Validated` を満たす。工業、在庫、輸送、装備庫接続、運用者、補給、交戦規則は残りのゲートを所有する。一つでも満たさない兵器は、その作戦の手元戦力へ数えない。

ゲームは設計可能な全兵器を毎回生成または全件走査しない。登場済みの装備、明示的な候補、契約・クエストで要求された候補だけを有界集合として評価する。外部MOD装備も、汎用タグまたは個別Adapterで接続されたものだけを候補にする。

## 任務別の能力値

兵器種 `j` の任務 `m`、環境 `e` における基礎能力を、必要な特性 `p_ij` の重み付き合成として扱える。

```text
q_j(m,e) = sqrt( sum_i alpha_i(m,e) * p_ij(e)^2 )
sum_i alpha_i(m,e) = 1
```

特性には火力、防護、機動、探知、通信、妨害耐性、持続性等を必要な分だけ置く。`alpha_i` は任務と環境が所有し、陣営の恒久補正にしない。基礎能力の単純合計 `B_g = sum_j n_gj * q_j` は編成比較の入口にだけ使い、最終戦果とみなさない。

## 任務連鎖とネットワーク

一つの攻撃連鎖 `K` を、探知、識別、決心、伝達、追尾、交戦、効果確認等の必要段階で構成する。各段階の成功確率を `p_l` とすると、連鎖の成立確率は次で表せる。

```text
P_K = product_l p_l
```

同じ目標へ独立または部分的に独立した複数経路がある場合、少なくとも一つが成立する概算は次とする。

```text
P_mission = 1 - product_K (1 - P_K)
```

経路の独立性が低い場合は相関補正を入れる。同じ通信中継、同じセンサー、同じ指揮所へ依存する二経路を、完全な冗長性として二重計上しない。

戦闘ネットワーク `G` の任務能力は、利用可能な連鎖の価値を合成して表す。

```text
C(G) = sum_K weight_K * P_K * mission_value_K
I(v) = ( C(G) - C(G without v) ) / C(G)
```

`I(v)` はノード `v` を失った時の能力低下率であり、指揮所、通信中継、偵察機、電子戦装置、弾薬拠点等の重要度を示す。OMGによる後方攻撃、対ドローン戦、電子戦は、単純なダメージ増加ではなく、主にノード、接続、遷移確率を変える。

## 状態遷移と損耗

部隊 `g` の状態を、少なくとも次の区分で保持する。

```text
x_g = [Ready, Degraded, Disconnected, Resupply, Lost]
x_g(t + dt) = T_g(m,e,a) * x_g(t)
```

`T_g` は任務、環境、双方の行動 `a` によって変わる遷移行列である。電子妨害なら `Ready` から `Disconnected`、補給攻撃なら `Ready` から `Resupply`、整備・通信回復なら逆方向の遷移を増やす。永久損失と一時的な機能停止を分ける。

一定時間の攻撃による期待有効打は、次を最小形とする。

```text
lambda(a -> b) = opportunities_a
               * P_mission
               * P_hit
               * P_effect
               * dt
```

実際の損害・機能停止は `lambda` を平均とする二項分布、ポアソン分布その他の有界な確率処理から得る。大量の安価な無人機には発進数と同時管制数、再使用機には回収・整備、誘導兵器には在庫と補充を必ず反映する。

## 補充と工業

次周期の即応数は、現在数から損耗を引き、修理完了、製造完了、到着済み補充だけを加える。

```text
Ready(t + dt) = Ready(t)
              - irreversible_losses
              - temporary_unavailability
              + repaired
              + manufactured_and_delivered
              + reconnected
```

「製造できる」は、損失を同じTickで無効化しない。材料、エネルギー、製造枠、工数、品質確認、輸送、運用者、弾薬・部品の供給が完了して初めて `manufactured_and_delivered` へ入る。高性能な帝国系少数品と、補充しやすいユニオンモデルの差は、この流れの性能、時間、損失耐性として表す。

## ドローン・電子戦の表現

無人機は、次の役割を組み合わせるノードとして実装する。

- 偵察・目標識別
- 通信・航法中継
- 直接攻撃・徘徊攻撃
- 電子妨害・電磁情報収集
- 囮・飽和・被害判定
- 迎撃・対無人機警戒
- 補給・回収・救命

電子戦は「ドローンへ一律倍率」を掛けない。対象の周波数、通信方式、航法、視線、距離、出力、地形、代替経路に応じ、特定段階の `p_l` または状態遷移を変える。自律航法、光ファイバー、慣性航法、事前計画経路等がある機体は影響を減らせるが、識別、再任務化、効果確認等の別段階が残る場合がある。

## 情報と表示

シミュレーションが持つ真の状態 `x` と、プレイヤーまたはAIが観測した推定 `x_hat` を分ける。推定には最終観測時刻、信頼度、誤差幅を持たせる。偵察、通信、欺瞞、情報共有は `x_hat` の精度を変え、未観測の敵戦力を完全表示しない。

プレイヤーには一つの不透明な「戦闘力」だけを示さず、少なくとも即応戦力、任務連鎖、補給、通信、推定精度、主要制約、予測幅を説明する。数式は裁定を一貫させる内部道具であり、結果の理由を隠すために使わない。

## 検証条件

- 単体性能が高い編成でも、観測または通信が切れれば任務能力が下がる。
- 安価な無人機の大量投入は有効になり得るが、同時管制、電磁環境、在庫、発進、補充によって上限を持つ。
- 同一ノードに依存する冗長経路を二重計上しない。
- 一時的な妨害と永久損失を区別し、回復処理を検証できる。
- 全兵器・全外部MOD・全地域を毎Tick走査しない。
- 陣営名だけでロシア式、中国式、帝国式等の固定能力倍率を与えない。
- 同じ初期状態を多数回試行した時、平均と分散が意図した範囲へ収束する。

具体的なDef、係数、更新頻度、乱数方式、UIは実装予約である。最初の縦切りでは一地域、一任務、少数の明示ノードで状態遷移と理由表示を検証する。
