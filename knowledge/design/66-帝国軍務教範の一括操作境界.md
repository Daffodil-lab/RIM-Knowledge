# 66. 帝国軍務教範の一括操作境界

帝国軍務教範は、プレイヤーが選んだ対象とProfileに対して、バニラの正本trackerと公開操作を一括実行する。各一括操作は、態勢遷移へ自動的に含める操作、同じ画面から別確認で実行する操作、別制度へ移動する操作の三群に分ける。

## 収録基準

態勢遷移へ含める操作は、次の全条件を満たす。

- 教範が登録した対象だけへ適用できる。
- 変更後の値をバニラの正本trackerまたは登録設備が保持する。
- 現在値との比較で冪等に再計算できる。
- 攻撃対象、能力対象、政治判断を新たに選ばない。
- 資源消費、依存症、手術、称号等の不可逆な結果を確定しない。
- 不足時に代用品または別対象を黙って選ばない。

不可逆または政治的な操作は、態勢切替の事前画面へ件数と不足を表示できるが、別の確認操作として実行する。

## 態勢遷移へ含めるPawn操作

| 操作 | バニラ所有者・公開経路 | 教範の処理 | 失敗結果 |
|---|---|---|---|
| 徴兵・徴兵解除 | `Pawn_DraftController.Drafted` | Profileが指定したPawnだけを段階的に変更し、教範が変更した徴兵状態を記録する | 非Spawn、ダウン、精神状態等は除外する |
| 射撃許可 | `Pawn_DraftController.FireAtWill` | 戦闘Profileの希望値へ合わせる | drafter不在は除外する |
| 行動区域 | `Pawn_PlayerSettings.AreaRestrictionInPawnCurrentMap` | Map内のArea参照を直接設定する | 別Map、削除済み、未解決Areaは保留する |
| 勤務表 | `Pawn_TimetableTracker.SetAssignment` | 24時間分の差分だけを設定する | tracker不在は除外する |
| 服装方針 | `Pawn_OutfitTracker.CurrentApparelPolicy` | 方針を切り替え、装備不足を報告する | 不足品を強制装備せず、現在装備を勝手に廃棄しない |
| 薬物方針と携行 | `Pawn_DrugPolicyTracker.CurrentPolicy` | 依存維持、娯楽、定期使用、携行数をProfileへ合わせる | 即時服用は行わない |
| 医療設定 | `Pawn_PlayerSettings.medCare`、`selfTend` | 部署別の治療水準と自己治療方針を適用する | 医療行為そのものはバニラ仕事へ委ねる |
| 作業優先度 | `Pawn_WorkSettings.SetPriority` | 医療、消火、運搬、修理等の登録項目だけをProfileへ合わせる | 未解禁または実行不能な仕事は除外する |

服装方針は`OutfitForcedHandler`を使用しない。教範は全員へ強制着用を付けず、バニラの品質更新と着替えを妨げない。警戒時は不足品と未着替え人数を表示し、戦闘開始を自動延期しない。

## 保存隊形と移動

保存隊形は、基準点、向き、役割枠、相対セルを持つ教範Profileとして保存する。入植者欄の並び順ではなく、安定した部隊枠IDから各Pawnのセルを決める。

バニラの`MultiPawnGotoController`は実発令部分を再利用できないため、教範は各Pawnへ通常の`Goto` Jobを発令する薄いAdapterを持つ。発令直前に次を検査する。

- 同じMapに存在し、徴兵可能であること
- 目的セルがMap内にあり、立入可能であること
- 他の必須枠と重複しないこと
- 禁止区域、火災、真空、深水、収容設備の作業セル等の登録危険を侵害しないこと
- 現在の手動命令を上書きする場合は事前表示されていること

必須枠が成立しない場合、隊形移動群は発令しない。任意枠の欠落は該当Pawnだけを保留できる。経路探索を一Tickへ集中させず、2～4 PawnずつJobを発令する。

保存隊形は戦術AIではない。遮蔽評価、敵選択、自律的な前進・後退、追撃、救助対象選択を行わず、プレイヤーが指定した基準点へ既存の移動命令をまとめる。

## 登録設備

態勢遷移が直接変更できる設備は、教範対応の公開Compまたは明示的なRelayへ登録されたものだけとする。

| 設備 | 適用境界 |
|---|---|
| カエラヴィ指揮扉 | 登録された保安Profileに従って開放維持、閉鎖要求、通行区分を変更する |
| 砲塔Relay | 登録砲塔群の電源・警戒状態をRelayの公開状態から変更する。目標は選ばない |
| 電力・設備Relay | 平時、警戒、戦闘、復旧ごとの登録設備群を切り替える |
| 集合地点・避難所・病院 | 有効化するArea、寝床、備蓄先、表示を切り替える |

バニラの一般扉は永続的な施錠・開放維持の公開setterを持たず、バニラ砲塔はhold-fireと強制目標解除の公開契約が不足する。教範は全バニラ扉・砲塔をReflectionまたはHarmonyで所有し直さない。通常のPower SwitchやFlick作業を利用する場合は、即時変更ではなくバニラの作業命令として扱う。

## 別確認で行う一括操作

次の操作は同じ管理画面から実行できるが、態勢遷移には含めない。

| 操作 | 確認内容 | 実行境界 |
|---|---|---|
| 戦闘刺激剤の一括服用 | 対象、適合軍務ゼノジャーム、禁忌、既服用、在庫、依存結果 | 対応薬を所持するPawnへIngest Jobを2 Pawnずつ発令し、結果数を返す |
| 思想役職の一括叙任 | 要件、現在役職、政治的Thought、能力再計算 | `Precept_Role.Assign/Unassign`を使用し、一Tick最大4 Pawnへ適用する |
| ゼノジャーム・手術 | 対象、医療条件、不可逆性、資源 | バニラの医療・遺伝子工程を予約し、直接状態を付与しない |
| 砲撃・爆撃・超能力・遺伝子能力 | 対象地点、使用者、消費、味方被害 | 対象選択と最終確認をプレイヤーが行う |
| シャトル・車両・艦艇の発進 | 乗員、積荷、燃料、到着先 | 個別の出撃画面と発進処理へ渡す |
| 許可証、名誉、称号、クエスト | 消費、外交、政治的結果 | Royaltyまたはクエストの正規処理へ渡す |

戦闘刺激剤は`警戒`で携行と不足検査まで行い、`戦闘`ボタンとは別の`刺激剤を支給・服用`確認を持つ。結果は`82名中74名へ発令、4名禁忌、2名既服用、2名不足`のように返す。

## 管理用の反復工程

教範画面には、態勢と独立した管理用一括操作を接続できる。

### 作業指示Template

作業台のRecipe、回数、備蓄先、材料Filter、技能範囲等をTemplateとして保存し、互換する再建設備へ`Bill.Clone()`と公開`BillStack`操作で再適用する。設備破壊後は自動的に同一設備と決めつけず、登録済み設備を低頻度で照合するか、プレイヤーの`作業指示を復元`操作で適用する。Template fingerprintにより二重追加を防ぐ。

### ガウランレン管理

既存接続樹について、希望接続率と希望ドライアド種を一括設定し、剪定と種変更はバニラWorkGiverへ委ねる。接続儀式を飛ばしてPawnを直接接続せず、活動中ドライアドを性能目的でThingOwnerへ移さない。ドライアドを抽象化する管理林苑は別の設備仕様として扱う。

### Anomaly収容方針

収容体の維持、研究、処刑、解放、バイオフェライト抽出、研究許可を一括表示・設定できる。処刑と解放は個別または群単位の別確認を要求する。特定収容台への移送は、収容強度、空き、作業セル、到達性を検査してからバニラの運搬・移送Jobへ渡し、`ThingOwner`へ直接移さない。

収容設備の登録時は、周囲に作業者が立てる到達可能セルがあることを性能安全条件として検査する。成立しない設備は自動割当から除外し、遮蔽物、岩塊、壁等の阻害要因を表示する。

## 別制度へ委ねる操作

貴族の部屋要件、共有士官宿舎、徴税官の要請、名誉交換、占領地行政、恒久的な軍階級は、人事、宮廷、外交、内政台帳が所有する。教範画面は該当管理画面へ移動できるが、態勢遷移で部屋所有権、称号、名誉、外交関係を変更しない。

## 事前表示と結果

全一括操作は実行前に次を表示する。

- 対象総数と操作種別ごとの件数
- 既に希望値と一致する対象
- 手動例外と、上書きする場合の対象
- 到達不能、実行不能、別Map、精神状態等による除外
- 装備、薬物、医薬品、弾薬、燃料の不足
- Jobまたは経路探索を伴う命令の予想Queue数
- 不可逆操作と政治的結果

各操作は次の結果コードを返す。

| 結果 | 意味 |
|---|---|
| `適用済み` | 希望値へ変更した |
| `既に一致` | 変更せず成功とした |
| `保留` | 条件または在庫が整えば再試行できる |
| `除外` | 死亡、離脱、別Map、対象外等により今回処理しない |
| `手動例外` | 現在の手動設定を維持した |
| `拒否` | 必須ガードを満たさず操作群を開始しなかった |
| `安全停止` | 適用途中の変化により未発令分を停止した |

代用品、別Pawn、別設備、別の収容先を選ぶ場合は、Profileに明示された優先順位とガードがある場合だけ行う。候補が尽きた時は自動再試行ループを作らず、保留と理由を返す。

## 保存と操作所有権

バニラtrackerと設備が現在値を所有し、教範は希望値、対象、手動例外、操作ID、発令結果だけを所有する。Job Queueそのものを第二の正本として保存しない。

ロード後は希望値と現在値を比較し、可逆的な未完方針だけを再構築する。移動、服用、手術、移送、能力使用等の発令済み操作は自動的に繰り返さず、結果が不明なら再確認待ちにする。

## 性能条件

- 教範の待機中は全Pawn、全設備、全Bill、全収容体を走査しない。
- 自前の名簿・設備登録、態勢変更、方針変更、Spawn・Despawn通知をdirty契機にする。
- 外部変更を捕捉する補助照合は、登録対象を250～1000 Tickへ分散して検査する。
- 非経路方針は一Tick最大16～32 Pawn、役職は最大4 Pawn、Job・経路探索・服用・移送は最大2～4 Pawnへ適用する。
- 管理画面は行を仮想化し、表示中の約30行でLayoutとRepaintの平均`2ms/frame`以下を設計予算とする。
- Harmony patchを通常の一括操作成立条件にせず、全PawnのTick、Needs、Renderer、JobDriver、WorkGiverへ共通patchを追加しない。
- 性能値は実装後に同一セーブの無効・有効差分で測定し、設計予算を実測値として報告しない。

## 受入条件

1. 百人へ一括方針を適用しても、同一Tickへ百件の経路探索を発生させない。
2. 手動例外、在庫不足、別Map、死亡、精神状態を区別して件数と理由を返す。
3. 一括服用、役職叙任、能力使用、発進、政治操作が態勢ボタンだけで実行されない。
4. 保存隊形はプレイヤー指定の基準点へ通常移動を発令し、敵選択や自律戦術を行わない。
5. 一般バニラ扉・砲塔を非公開状態の書換えで制御せず、登録対応設備だけを変更する。
6. 作業指示、ガウランレン、収容方針はバニラの正本状態と仕事を維持し、直接Thing移送または儀式省略を行わない。
7. 保存・ロード後に服用、移動、手術、移送、能力使用を重複発令しない。
