# 7. 製品ファミリーの新しい境界

## 7.0 Core共通の公式依存

CoreはDLC非依存製品として設計しない。開発・配布・標準試験は、RimWorld 1.6にRoyalty、Ideology、Biotech、Anomaly、Odysseyを全て有効化した環境を前提とする。Coreの`About.xml`は次を必須依存として宣言する。

```text
Ludeon.RimWorld
├─ Ludeon.RimWorld.Royalty
├─ Ludeon.RimWorld.Ideology
├─ Ludeon.RimWorld.Biotech
├─ Ludeon.RimWorld.Anomaly
└─ Ludeon.RimWorld.Odyssey
   ↓
Shion Race: Core
```

DLC欠落時の縮退モードや代替Defを製品要件にしない。各DLC機能をどのサブシステムが所有するかは実装時に明示し、無関係なRuntimeへ具象型を逆流させない。現在の具体的なDLC一覧、追加DLC発表時の更新規則、検証条件は`シオンShion_Core_最終仕様_更新計画_v1.md`を正本とする。

## 7.1 一製品・内部モジュール

```text
Shion Race: Core
├─ Base（必須）
│  ├─ 人格・身体・独立開拓団開始
│  ├─ Pawn Foundry・個体登録・Clone・Dormant保管・回収再生
│  ├─ 共通研究・建築・装備
│  └─ 文化・救援・クエスト基盤
├─ Kombinat（必須・常駐Runtime）
│  ├─ 資源台帳
│  ├─ 原子的予約
│  ├─ Kombinat HubとStorage Unit
│  ├─ 生産・消費・流通の統合操作
│  └─ 依存計画・生産実行（αで完全実装）
└─ The Hive（同梱予定・任意起動・実装後回し）
   ├─ 単一中枢人格
   ├─ Core Projection／端末
   └─ WorkerSlot等の固有Adapter

Shion Race: Red Star（製品境界は保留）
├─ 案A: Core同梱の任意モジュール
└─ 案B: Coreを前提とする外部拡張

その他の時代・装備・人物・物語拡張（外部）
└─ Coreの公開境界を利用する
```

## 7.2 統合しても同一化しない

製品をCoreへ統合することは、正史上の社会形態やコード責務を一つに溶かすことではない。

- Kombinatは通常CoreでもHiveでも使う汎用Runtime。
- The Hiveは通常シオン社会の代表ではない例外構造。
- Red Starは通常Core開始と異なる政治・補給関係を持つ。
- 内戦拡張は現代同盟の標準装備・標準倫理へ上書きしない。

## 7.3 なぜHiveもCoreへ含めるか

The Hiveは身体・人格・Kombinat・救援というCoreの主題を極端な一例として扱う。プレイヤーに別MODの依存解決を要求するより、Core内で任意起動にした方が互換と導線を管理しやすい。

一方、通常開始へ常時混ぜると例外が標準に見える。したがってコンテンツ、研究、シナリオ、生成、UIは内部モジュールとして隔離する。

これは最終配置の判断である。α版にはThe Hiveの固有コンテンツも空の将来境界も含めない。本体実装はCore Base、Kombinat、通常遠征の生活・救援・工業、独立勢力、Red Star境界が安定したβ後期まで延期し、Core完成宣言までに任意起動モジュールとして完成させる。

## 7.4 Red Starの製品境界は保留する

Red Starは本国が正式に承認・派遣し、物資、技術、情報、輸送・回収、必要時の軍事支援へ優れた品質と継続性で接続する特定の開拓団である。その代わりに、正式任務、報告と監査、救援・保護義務、交戦規則、補給基盤の維持等を負う。支援と責務のイベント、装備、数値は独自のプレイループになるため、Coreの複数開始立場へ固定しない。

ただし、独自プレイループを持つことだけでは外部製品にする十分な理由にならない。Core内で選べる正式派遣開始として提示する利点も大きい。したがって、次の二案を残す。

| 案 | 利点 | 主なリスク |
|---|---|---|
| Core同梱の任意モジュール | 導入が一回、開始画面で関係を比較しやすい、Coreとの版ずれがない | Core容量とテスト面積が増え、通常開始との境界が曖昧になり得る |
| Core前提の外部拡張 | 支援ループ、装備、クエストを独立して更新・調整できる | 導入・依存が増え、Red Starが本編外の派生に見え得る |

配布境界を決める前に、支援要請、到着、情報支援、軍事支援のうち一つを小さな縦切りとして設計する。コードは`Shion.RedStar`等の独立Assembly／名前空間へ隔離し、Core同梱にも外部配布にも移せるようにする。正史上の固有性と製品上の置き場を混同しない。
