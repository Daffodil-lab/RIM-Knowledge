# J. Creditと関連台帳

次を一つの受入Scenarioで確認する。

1. 標準Shion開始は同盟Credit AccountだけをProfile値で一回初期化し、カエルムMark、債務、租税Ledgerを生成しない。
2. 対応ProfileはCredit、Mark、債務、租税を別IDで初期化し、一つの値へ統合しない。
3. Credit認定・予約・使用・返還、Mark決済、債務返済、租税徴収、Thing受渡しを含む取引が全部成功または全部失敗する。
4. 同じ`idempotency key`の連打、取消、失敗後再試行、保存・ロード後再送で二重加算、二重返済、二重徴収、Thing複製を起こさない。
5. 非物理Account／Ledgerはwealthを変えず、受領した実Thingだけが通常どおりwealthへ加算される。
6. 保存往復後に各ID、scope、利用可能量、予約量、残高、債務額、租税額、Transaction結果が一致する。
