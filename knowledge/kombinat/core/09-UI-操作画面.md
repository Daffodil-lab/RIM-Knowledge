# 9. UI

α版は、Field Ledger Terminalを選択して開く一つの内政管理Windowを持つ。TerminalのGizmoは特定のFactoryまたはStorageを先に選ばなくても全登録Pageと全公開操作へ到達できる正規入口である。個別工場、Storage、EndpointのGizmoは同じWindowを対象Page・対象Record付きで開く文脈ショートカットとする。保管基盤が所有する情報とKombinatが所有する情報は同じWindowから辿れてよいが、内部状態の所有者は混同しない。

## UI駆動実装契約

工業機能は、実装対象となる画面の基準画像と画面契約を先に固定し、画像に現れる情報、状態、操作から必要なView Model、Application操作、保存状態、失敗結果を定義して実装する。基準画像は情報階層、用語、相対配置、選択状態、操作入口を所有し、StorageとKombinatの正本が物理Thing、予約、Request、Plan、Job、Batch、Facility、Accountの状態を所有する。

最初の工業縦切りは次の順序で固定する。

1. 共通Window Shellで、Title bar、左Page rail、選択状態、状態語、機能識別色、確認、取消、閉じる操作を固定する。
2. 生産概要で、検索、Filter、Request一覧、選択中Request、工程、現在の停止原因、最大の遅延要因、主要操作を固定する。
3. 生産依頼作成で、品目、数量または目標在庫、優先度、納入先、総材料、予約、不足、中間品、概算時間を固定する。
4. 生産依頼詳細で、工程、予約、根本原因、影響、調達、設備確認、一時停止、取消を固定する。
5. 同じ用語と状態をStorage、設備、物流、財務へ接続する。

画像内の数値は、対応する正本状態または再構築可能な派生索引が存在する時だけ表示する。状態所有者がない値は画面専用の疑似残高として保持せず、View Model契約を追加してから表示する。基準画像に必要な状態を追加した場合は、保存、取消、復旧、性能試験を同じ縦切りへ含める。

## RimWorld 1.6適合契約

統合端末はVerseの`Window`として`Find.WindowStack.Add`から開く。Field Ledger Terminalの`Command_Action`は対象Recordを要求せず`概要`Routeで全Pageを開き、工場またはStorageの`Command_Action`は選択中Facility、Storage、初期Pageを同じWindowへ渡す。通常表示の基準寸法は1100×680論理pxとし、利用可能画面が小さい場合はWindowを画面内へ収め、Page railと一覧をScrollViewへ退避する。本文文字は`GameFont.Medium`、`GameFont.Small`、必要最小限の`GameFont.Tiny`を使用し、画像専用フォントを実行時要件にしない。

共通Shellは暗いgraphite色のTitle bar、左Page rail、本文領域、標準Closeで構成する。在庫、生産、設備、物流、財務はRimWorld標準UIへ連続する暗色の運用Paneを使用する。ホーム、資料庫、チュートリアルは同じ暗色Shellの本文領域内に限って技術用紙、記録写真、台帳意匠を使用する。紙面意匠はWindow全体、Map、Inspect Pane、Gizmoを覆わない。

WindowはRimWorldの入力と時間進行へ次のように接続する。

- `doCloseX = true`、`doCloseButton = false`で右上の標準閉じる操作とEscを使用する。
- `absorbInputAroundWindow = false`、`forcePause = false`で、管理中も通常のゲーム時間進行とMap確認を維持する。
- Title barの最大化／復元操作は同じWindow、Page、選択Record、検索、Filterを維持して利用可能UI領域へ再配置する。通常表示ではMap、Inspect Pane、Gizmo、Main Tabを残し、最大化表示では大量一覧、工程、物流graph、取引履歴の表示面積を優先する。
- 表示モードは`KombinatTerminalSettings`が保持するUI設定であり、Ledger、Request、Storageへ保存しない。最大化しても全件再集計せず、増えた可視行と可視graph要素だけを描画する。
- Pageは`KombinatManagementPageDef`から左の縦Page railへ生成する。表示高を超えるPageは同じrail内の縦ScrollViewへ収め、選択中Pageを完全表示する。
- Page railは概要、在庫、生産、設備、物流、財務、資料庫を登録順に表示し、追加MODのPageをWindow本体の固定分岐なしで同じrailへ追加する。
- 選択設備のInspect Pane、Gizmo、Main TabはRimWorld本体が所有する画面要素をそのまま使用し、統合Window内へ複製しない。
- 文字入力は`Widgets.TextField`、数値入力は`Widgets.TextFieldNumeric`、操作は`Widgets.ButtonText`または`Widgets.ButtonInvisible`、品目Iconは`Widgets.ThingIcon`を使用する。
- 一覧は`Widgets.BeginScrollView`を使用し、可視行と前後の少数行だけを描画する。選択、Mouse Over、TooltipはRimWorldの標準Widgetsへ合わせる。
- 暗色Panel、細い罫線、状態Icon、資料Pageの紙Textureは事前読込したTextureを再利用し、`DoWindowContents`中にTexture生成、ファイル読込、全Map走査、全Request再計画を行わない。
- UI Scaleと翻訳後文字幅で切れたラベルはTooltipまたは詳細Paneへ送る。重要状態は色だけでなくIcon、状態語、配置を併用する。

## 生産概要の実装対応

| 画像要素 | 正本または派生元 | RimWorld側の表示・操作 |
|---|---|---|
| 検索とFilter | Page workerの一時状態と事前索引 | `Widgets.TextField`とButton。検索変更時だけ候補を更新する |
| 進行中、要対応、完成予定 | LedgerのRequest状態索引 | dirty eventで更新する集計View Model |
| Request一覧 | `ProductionRequestRecord`とProduction Catalog | 仮想化ScrollView、ThingIcon、選択行Highlight |
| 進捗と工程 | Plan、Job、Batch、Facilityの現在工程 | 選択Requestだけを読み、保存済み工程状態から描画する |
| 現在の停止原因 | 現在工程の`StatusReason`とStorage失敗結果 | 解決可能な原因、対象Def、数量を表示する |
| 最大の遅延要因 | 依存PlanとFacility Queueの有界診断結果 | 再計画時に更新した診断Projectionを表示する |
| 完了予定 | 工程時間、残量、Facility割当、待機理由 | 根拠が成立する時は概算時刻、成立しない時は「未定」を表示する |
| 問題を確認 | 選択Request ID | 同じWindow内の生産依頼詳細Pageへ移動する |
| 一時停止・再開 | Requestの`Suspended`状態と予約方針 | 冪等Application操作を呼び、結果Messageを表示する |
| 取消 | Request IDと関連予約 | 確認後に取消Operationを呼び、解放結果を表示する |

一時停止、完了予定、最大の遅延要因は、それぞれ保存状態、計算根拠、更新契約が完成するまで無効状態と説明Tooltipを返す。画面上の例示値だけで稼働中に見せない。

| Page | 必須内容 |
|---|---|
| 概要 | 収支、警告、実在庫、予約容量、Plan、Job、Batch、発注入口 |
| 在庫 | 名前、Icon、合計、入力予約、利用可能、容量、出力容量予約、検索、Filter、選択数・指定数・全量排出 |
| 生産 | 製品、発注数または目標在庫、優先度、必要材料、予約、不足、作成する中間品、総材料、概算時間、Queue、Pause、取消、完成数 |
| 設備 | Map Facility、台帳Facility、Profile、能力、稼働率、故障、保守、割当 |
| 物流 | Network、納入先、観測消費、Facility需要、不足見込み、輸送、目標数 |
| 財務 | Account残高、入出金、保留、失敗、契約、購入、売却、維持費 |

## 拡張契約

各Pageは`KombinatManagementPageDef`で`workerClass`、順序、表示名、説明、Icon、可視性を宣言する。WindowはDef一覧を順序で並べてworkerを一度だけ生成し、固定switch、固定enum、固定タブ配列を持たない。

追加MODは新しいPage Defと`KombinatManagementPageWorker`派生型を登録できる。αで内部機能が未完成のPageも削除せず、所有境界と拡張入口を示すworkerを持つ。設備の対応Pattern、処理間隔、速度は`KombinatFacilityProfileDef`、Account初期値は`KombinatLedgerDef`が所有し、UIコードへ値を埋め込まない。

## 管制塔と建築Gizmo

- Field Ledger Terminalは`統合端末を開く`を表示し、全登録Pageと全公開操作を持つWindowを`概要`から開く。
- 個別Factory、Storage、Endpointは同じWindowを対象Page・対象Record付きで開く。
- 内容物を選択して排出する。
- 全内容物を排出する。実行前に件数と対象Stack数を確認する。
- Pawn直接アクセスを許可、禁止、限定する。
- 接続Overlayを切り替える。

Terminalの停電、Network分断、台帳初期化失敗時もWindowと診断Pageを開ける。実行不能な操作は正本状態を変更せず、所有者の拒否理由を表示する。建築実体に保管された内容物の手動排出Gizmoは停電またはNetwork分断中も無効化しない。排出先がない場合は、内容物を維持して理由を表示する。

## Map表示

範囲と接続線は建築選択時、または明示的にOverlayを有効にした時だけ表示する。入庫、出庫、双方向、停止、遮断を区別し、実際の転送時だけ短いPulseを表示する。常時表示や毎Thingの常時Animationで通常画面を覆わない。

## 大量在庫

一覧は検索索引とevent更新を使い、毎frame全件走査しない。大量項目はページングまたは仮想化し、先頭500件だけを表示して残りを不可視にする仕様にはしない。

## 発注確認

発注確定前に、直接材料と全中間工程を合計した総材料を表示する。「作成する中間品」は既定では種類数と総数だけを要約し、展開時に工程別の必要数、在庫充当、作成数、設備、待ち理由を表示する。一回の確定で親Requestと必要な子工程を作成し、中間品ごとの手動発注を要求しない。
