# 9. Adopt / avoid table for Shion Nexus

| Monolyn player-practice pattern | Shion Nexus decision |
| --- | --- |
| Central Tower as colony-scale identity | Adopt structurally through Nexus Core and Tower Ledger. |
| Light as universal operating resource | Translate into CVE, but keep it compact and not labor-tax based. |
| Prayer schedule as resource production | Avoid for alpha; do not hide core loop in Schedule tab. |
| Memory Pillar capacity expansion | Use as future reference for explicit capacity buildings. |
| Baptism recruitment | Avoid in alpha; possible future Mercy/translation system with clear costs. |
| Destroyed terminal reconstruction | Adopt structurally as future terminal recovery, but alpha uses simple death/record rules. |
| Cross-base Tower sharing | Major future logistics reference, not alpha. |
| UI confusion from hidden progress | Avoid; expose state through Inspect and clear messages. |
| Late-game resource shortage solved by settings | Avoid by designing explicit economy curves and caps. |
| Compatibility with big UI/framework mods | Keep alpha UI small and vanilla-friendly. |
